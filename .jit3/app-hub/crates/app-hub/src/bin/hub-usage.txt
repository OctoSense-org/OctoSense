hub — the OctoSense app hub command (ADR 0003)

  hub keygen <new path>                 create a signing key without overwriting; print its public half
  hub pubkey <key file>                 print a key's public half
  hub certify --anchor <f> --working <f>   anchor certifies a working key
  hub stamp <bundle>                    write the bundle's digest into its manifest
  hub sign-manifest <bundle> --key <f> --key-id <id>
  hub publisher-prepare <bundle> --repository <owner/repo> --repository-id <id> --owner-id <id>
              --workflow <.github/workflows/publish-app.yml> --tag <vVERSION> --commit <sha>
              --out <outside-bundle/octosense-app-manifest.json>
  hub publisher-attach <bundle> --attestation <Sigstore-v0.3-bundle.json>
  hub publisher-verify <bundle> [--catalog <authenticated catalog>]
  hub publisher-pack <bundle> --out <outside-bundle/app.bundle.pack.json> [--catalog <authenticated catalog>]
  hub publisher-unpack <app.bundle.pack.json> --out <new staging directory> [--catalog <authenticated catalog>]
  hub publisher-entry <bundle> --catalog <authenticated catalog> --out <index.json>
  hub check <bundle> [--catalog <f> [--anchor <hex>]] [--allow-unsigned] [--publisher-key id=hex] [--json] [--system-app] [--advisory-db <dir>]
  hub publish <bundle> --catalog <f> --key <f> --anchor-cert <hex>
              --publisher <id> [--repo <url>] [--commit <sha>] [--out <dir>]
  hub withdraw <app or component> --version <v> --reason <text> --catalog <f> --key <f> --anchor-cert <hex>
  hub remove <app> [--version <v>] --catalog <f> --key <f> --anchor-cert <hex> [--out <dir>]
              (drops the entry, its index file and its artifacts; for a
              publish that should never have been offered — withdraw otherwise)
  hub scan <bundle> [--reviewer <cmd>] [--packet <out.json>]
             [--publisher-key id=hex] [--catalog <f> [--anchor <hex>]] [--system-app]
  hub verify <catalog> --anchor <hex>
  hub component-info <file.wasm>        print a function file's kind, imports and exports
              (with WIT parameter and result types) as JSON
  hub component-prepare <file.wasm> --draft <component.json> --out <file>
              [--repository <owner/repo> --repository-id <id> --owner-id <id>
               --workflow <.github/workflows/x.yml> --tag <vVERSION> --commit <sha>]
              describe a shared component from its file: an unsigned development
              release, or with the GitHub identity the subject to attest
              (--out .../octosense-component.json)
  hub component-pack <release.json> --wasm <file.wasm> [--attestation <bundle.json>]
              [--allow-unsigned] --out <new directory>
  hub component-check <release.json> --wasm <file.wasm> [--catalog <f> [--anchor <hex>]]
              [--allow-unsigned] [--json]
  hub component-entry <release.json> --wasm <file.wasm> --catalog <authenticated catalog>
              --out <index.json>
  hub component-publish <release.json> --wasm <file.wasm> --catalog <f> --key <f>
              --anchor-cert <hex> --publisher <id> [--repo <url>] [--commit <sha>]
              [--out <dir>] [--allow-unsigned]
  hub catalog-prepare --base <authenticated-catalog> --candidate <catalog.json>
              --artifact-root <reviewed-tree> --out <catalog-v2.payload.json>
  hub catalog-envelope --catalog <catalog-v2.payload.json> --attestation <bundle.json>
              --out <catalog-v2.json>
  hub catalog-verify <catalog-v2.json>

Use hub help or --help / -h with any command for this usage (no files changed).
keygen refuses existing files and symlinks. New keys are owner-only (0600)
on Unix; on other platforms protect the containing directory with its ACL.
scan permits unsigned development bundles, but signed bundles still need a
trusted publisher key (explicitly or from a verified catalog).
check/scan --system-app check a shipped os.* bundle with the system runner's
limits, allowing an unsigned development bundle. Other ids are refused in
this mode. publish never accepts --system-app or an os.* bundle.

publish also accepts --reviewer <cmd> (the agent scan; a reject stops the
publish, human-review stops it until --reviewed) and writes
<artifact>.pack.json beside the artifact for HTTP delivery.

check is the gate: a publisher runs it before submitting, the hub runs the
same code after. publish re-runs it, copies the bundle into the artifact
store and signs the catalog.

Shared components (App Hub ADR 0003) are published like apps: the release's
GitHub workflow runs component-prepare, attests the subject and runs
component-pack; reviewers run component-check, admins component-entry for a
catalog candidate. component-publish signs a legacy development catalog only.

GitHub publisher commands require public GitHub-hosted tag-push provenance.
prepare refuses sealed manifests; attach and pack never restamp. Candidate
entries confer no authority until the protected admin workflow attests the
exact catalog. Legacy app ownership cannot be adopted by GitHub provenance. No catalog is published by these commands.
