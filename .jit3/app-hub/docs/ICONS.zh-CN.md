# 应用图标与随包素材

[English](ICONS.md) | 简体中文

通过 App Hub 发布的每个应用都有一个自己的图标：图标随应用包发布，并在 `listing.json` 中声明。先读 [开发你的第一个 Hub 应用](FIRST-APP.zh-CN.md)；商店信息和准入的完整契约见 [发布参考](PUBLISHING.zh-CN.md)。

## 维护唯一的规范图标

把图标放在应用自己的仓库中，并随应用包发布：

```text
bundle/
  manifest.json
  listing.json
  assets/
    icon.svg
  screenshots/
    01-main.png
```

在 `listing.json` 中设置 `"icon": "assets/icon.svg"`。图标为 PNG 时，改用 `assets/icon.png`，并相应修改这个字段。路径相对于应用包根目录，而不是仓库根目录。这些文件名只是约定，任何相对于应用包的有效路径都可以。第 1 版商店信息 schema 没有 `dark_icon` 或 `adaptive_icon` 字段，而商店信息解析器会拒绝未知字段。

启动器和商店读取的都是这一处声明。不要为启动器、最近任务、商店列表项或详情页另存副本并单独编辑。构建需要其他格式时，从同一份源文件导出。

## 技术要求与检查方

`hub check` 在发布前运行准入检查，其中包括商店信息解析器。已安装图标加载器是每个 OctoSense Shell 都会链接的代码，用来绘制已安装应用的图标。加载器拒绝图标素材时，Shell 会改用自带的通用图标。

| 要求 | 检查方 |
| --- | --- |
| 声明图标，并把声明的文件放进应用包 | `hub check` |
| 使用相对于应用包的 PNG 或 SVG 路径：不以 `/` 开头、不含 `..`、不是 URL | 商店信息解析器 |
| 不附带符号链接；整个应用包控制在 8 MiB 以内 | `hub check` |
| 图标文件控制在 1 MiB 以内，且为正方形 | `hub check` 和已安装图标加载器 |
| PNG 控制在 1024×1024 像素以内，且是有效的 PNG 数据 | `hub check` 解码图片；加载器检查文件头和尺寸 |
| 使用可解析的 SVG，其 `width` 和 `height` 为相等的数值，或者 `viewBox` 为正方形；不使用 `<script>`、`<foreignObject>` 或 `on…` 事件属性；CSS 不从文件之外加载任何内容（不用外部 `url()`，也不用 `@import`）；不使用 CSS 转义或注释，因为它们可能隐藏 URL | `hub check`；加载器检查 SVG 能否解析、是否为正方形 |
| 让图标轮廓清晰、留白合适、对比度足够 | 你自己的视觉评审 |

`hub check` 检查表中的文件规则，**不检查图标的外观**。请在目标 Shell 中测试图标。

对应源码：[商店信息解析器](../crates/app-policy/src/listing.rs)、[准入检查](../crates/app-hub/src/gate.rs)、[应用包结构检查](../crates/app-hub/src/admission.rs) 和 [已安装图标加载器](../crates/app-hub-app/src/icons.rs)。

## 设计与导出建议

- 几何图形优先用 SVG。使用正方形 `viewBox`（例如 `0 0 64 64`），显式指定填充色和描边色，并用简单的路径、矩形和圆形绘制。
- 保持 SVG 自包含：文字一律转为轮廓，不嵌入脚本，也不引用外部字体、样式表或图片。SVG 命名空间 URI 只是标记的一部分，不算外部依赖。避免使用滤镜、蒙版等高级特性；如果要用，先在 Makepad 的原生渲染器中验证。
- 位图素材导出为 512×512 或 1024×1024 像素的正方形 PNG，不超过 1 MiB。如果设计用到了透明效果，就保留透明通道。
- 只用一个易于辨认的图形。应用名称留给启动器和商店的标签显示，不要画进图标。避免小字、过于细碎的细节和照片式的杂乱画面。
- 内部留白要均衡。先留出 10% 到 15% 的内边距，再与启动器中相邻的图标比较视觉大小。准入检查不会测量留白。
- 如需品牌背景底板，把它画进素材里。不要假定启动器或商店会添加背景、蒙版、阴影或着色。保留素材本身的颜色。
- 设计源文件和来源记录不要放进发布的应用包，应用运行时要用到的除外。

让每个应用都有自己的视觉标识。带 OctoSense 徽标的购物袋是 App Hub 商店本身的标识；不要在其他应用的图标中使用这个购物袋或 OctoSense 徽标。

## 评审与发布

1. 在浅色和深色背景上，分别以 24、32、48 和 64 像素查看图标。
2. 确认原生启动器以及 Hub 的列表视图和详情视图都显示预期的素材：没有裁切、没有多余的着色，也没有退回通用图标。
3. 更换已安装应用的图标时，测试从上一版本更新的过程。
4. 最后一次修改素材或截图之后，按照 [生成最终字节](SUBMITTING.zh-CN.md#5-生成最终字节) 中的说明，运行 `hub stamp`，再运行一次 `hub check`，然后签名。每次发布都要使用新版本号：准入检查会拒绝已经发布过的版本。

## 内置原生应用

对编译进 Shell 的原生应用，也采用同样的归属约定：声明一份规范素材，并通过构建的资源映射把它嵌入。App Hub 自己的原生商店就是这样做的：它在 `crates/app-hub-app/` 中的 `listing.json` 只有 `schema` 和 `icon` 两个字段。这个文件是**仅用于图标的原生构建声明**，不是一份完整、可发布的商店信息。原生应用随 Shell 一起发布，不作为 Hub 应用包安装。原生应用如果有主题变体，就在同一个共享函数中确定使用哪个变体，让启动器和商店保持一致。
