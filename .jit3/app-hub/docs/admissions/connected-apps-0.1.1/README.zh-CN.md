# 连接应用 0.1.1 预览版：准入记录

本记录对应序号 10 的已签名目录候选版本。三个发布者仓库的版本与下载已公开；
只有目录改动合并后，默认应用商店才会提供这些更新。原有 0.1.0 条目和文件、
官方锚点及工作密钥证书链、发布者公钥均未改变。

- Inbox Assistant：通知必须使用已准入的工作区模板及初始邮件数据，删除可执行源码替代路径。提交 #130。
- GitHub Notes：明确声明已有的、需用户同意的前台只读 Ask 助手及其指令。提交 #131。
- Google Calendar Sync：主机提供范围时显示过去 30 天 / 未来 366 天；旧主机没有范围元数据时明确显示范围不可用。提交 #132。

[admission.json](admission.json) 绑定发布者的不可变提交、标签、文件哈希、审查包、目录哈希及工具。
维护者助手在明确发布授权下检查了实际源码、隐私说明和全部八项回答；没有调用外部模型审查器。
`hub scan` 和 `hub publish` 的审查适配器只对哈希完全匹配的审查包返回已完成的结论，
未使用 `--reviewed` 绕过。各应用子目录保存发布输出及重复执行的签名准入检查。

[remote-downloads.json](remote-downloads.json) 记录匿名 HTTPS 下载及校验：所有 tar、pack、
SHA256SUMS 均匹配；解码后的文件与不可变源码标签、目录工件完全一致。发布下载的 pack
与 Rust 工具生成的 pack 字节一致，不可变隐私说明链接返回 HTTP 200。

[remote-store-install.json](remote-store-install.json) 来自真实的 Hub `Remote`、解包及 `Store`
执行：三个应用均通过全新签名安装、从 0.1.0 更新、保留虚构本地数据、更新前继续打开旧版、
准备启动校验、助手文件读取，以及新建 Store 实例后重新打开。临时配置已删除。
读取助手文件不等于启动助手。本次记录不证明原生界面、模型或真实提供者调用、实体发送批准、
Android 支持，也不代表默认主分支目录已经发布。

三个源码版本分别通过聚焦契约检查（Inbox 4 项、Notes 3 项、Calendar 3 项）。Calendar 的
实际范围函数另通过 4 项原生测试夹具检查。原始截图和历史验收仍标为历史证据；所有列表均
保留 macOS 开发预览限制。有限日程范围由 OctoSense #356 的主机实现，旧主机继续使用
“范围不可用”的回退提示。

跟踪文件检查未发现私有签名密钥字节、私有本地路径或凭据标记。可选的第三方密钥扫描曾把
公开 Git 提交号误判为密钥；详情如实记入 admission.json，未把未运行或失败的扫描说成通过。
旧版 0.1.0 记录逐字节保留。

复现命令见[英文说明](README.md#reproduce-the-store-verification)。先准备仓库要求的相邻源码，
仅在临时 example 路径不存在时复制助手，再运行固定提交的验证。目录时效性采用实际运行日期；
将来重跑时，历史目录过期导致拒绝是正确行为，不应绕过或替换后仍声称是同一证据。
