# Agent rules for AppCard (apps/appcard)

> **Any coding agent, or none.** These instructions work the same for Codex, Claude Code, Cursor, Gemini CLI, GitHub Copilot or a person at a terminal: every step is a shell command or a file edit, and nothing here needs a particular agent, model or vendor. `AGENTS.md` is the one source of truth; `CLAUDE.md` and `GEMINI.md` only import it for agents that look for those names.

> octos is this app's runtime (a Cargo dependency), not a development tool: you work on it with whatever coding agent you use.

All paths below are relative to `apps/appcard/` unless they say otherwise.

- **Framework sources.** Makepad, Octoscript and Octoscript-Makepad are the
  checkouts in `.sources/` at the repository root, prepared by
  `python3 tools/setup.py` from the root; the root `.cargo/config.toml` sets
  `OCTOSENSE_WORKSPACE=.sources`, which `app/app/build.rs` reads. Never vendor
  or fork them into this repository, and never add a second Makepad source:
  AppCard's crates are root-workspace members and take Makepad with
  `workspace = true`. This directory's own `tools/setup-native.py` and the
  other Python tools resolve the workspace from `OCTOSENSE_WORKSPACE` too, but
  outside cargo their default is still the parent of the repository root; set
  `OCTOSENSE_WORKSPACE=<repo>/.sources` when you run them (**unverified**
  after the move).
- **Pinned runtime.** The root `native-runtime.lock.json` selects the one
  Octoscript-Makepad release (this directory's copy names the same one), and
  that release's `runtime.json` pins the engines. Change the lock only as a
  deliberate runtime bump, together with the Makepad `rev` in the root
  `Cargo.toml` `[workspace.dependencies]`, and verify with
  `python3 tools/setup.py --check --cargo` from the root.
- **One octos.** Every octos crate comes from git octos-org/octos at the one
  rev in the root `Cargo.toml` (`octos-core` and `octos-cli` in
  `[workspace.dependencies]`; the OpenHarmony `nix` patch in `[patch.crates-io]`
  is from the same octos history). Leave it alone unless you are asked to bump
  octos; when you do, move them together and check
  `cargo tree --locked -p octos-app -i octos-core --target all --depth 0`
  shows a single source. Never add an octos submodule or a path dependency
  into an octos checkout.
- **Generated L0 corpora.** Do not hand-edit generated L0 content unless you
  are asked to. `a2app-l0/framework/catalog.md` is generated by
  `gen-catalog.py` from Octoscript's `docs/ui-l0-constructors.toml`, so change
  the source and regenerate. The `a2app-l0/apps/*/exemplar.card` reference
  cards are what L0 generation is prompted with and are compiled into
  `octos-app`. Change one only on purpose, and re-run the tests that
  `include_str!` it.
- **Test before committing.** From the repository root, run the clippy
  command from the README and
  `cargo test --locked -p octos-app-transport -p octos-app-store` (what CI
  runs; `cargo test --locked -p octos-app` for the app itself). If you touched
  `tools/core/` or `tools/setup-native.py`, also run
  `PYTHONPATH=tools python3 -m unittest core.test_native_runtime` from here.
- **One pull request.** Both shells mount AppCard through `module/`
  (`octosense-appcard`) from the same commit, so there is no pin to move in
  this repository. Rinx pins its own dependencies separately. Never
  force-push `main`.
- Follow the Makepad `script_mod!` DSL conventions of the `.sources/makepad`
  checkout (`Name: value`, `name := Type{}`, `+:` merge).
