# Agent rules for AppCard (apps/appcard)

All paths below are relative to `apps/appcard/` unless they say otherwise.

- **Sibling workspace.** Makepad, Octoscript and Octoscript-Makepad are
  checkouts beside the OctoSense-System-Apps repository (from here:
  `../../../makepad`, `../../../octoscript`, `../../../octoscript-makepad`),
  not submodules. Prepare them with `python3 tools/setup-native.py`. Never
  vendor or fork them into this repo, and never add a second Makepad source to
  `app/Cargo.toml`.
- **Pinned runtime.** `native-runtime.lock.json` selects the one
  Octoscript-Makepad release, and that release's `runtime.json` pins the
  engines. Change the lock only as a deliberate runtime bump. When you do, move
  the matching `rev =` pins in `app/app/Cargo.toml` and verify with
  `python3 tools/setup-native.py --check --cargo-manifest app/Cargo.toml`.
- **One octos.** Every octos crate comes from git octos-org/octos at the one
  rev in `app/Cargo.toml` (`octos-core`, `octos-cli`, and the `nix` patch share
  it). Leave it alone unless you are asked to bump octos; when you do, move all
  of them together and check `cargo tree -i octos-core --target all` shows a
  single source. Never add an octos submodule or a path dependency into an
  octos checkout.
- **Generated L0 corpora.** Do not hand-edit generated L0 content unless you
  are asked to. `a2app-l0/framework/catalog.md` is generated by
  `gen-catalog.py` from Octoscript's `docs/ui-l0-constructors.toml`, so change
  the source and regenerate. The `a2app-l0/apps/*/exemplar.card` reference
  cards are what L0 generation is prompted with and are compiled into
  `octos-app`. Change one only on purpose, and re-run the tests that
  `include_str!` it.
- **Test before committing.** In `app/`, run `cargo check` and
  `cargo test --workspace`, plus the clippy command from the README. If you
  touched `tools/core/` or `tools/setup-native.py`, also run
  `PYTHONPATH=tools python3 -m unittest core.test_native_runtime`.
- **Consumers repin by PR.** The OctoSense ROM (`home/apps/appcard`), the
  desktop shell and Rinx pin a rev of this repository. Never force-push
  `main`. Land changes here first, then open a PR in each consumer to move its
  pin.
- Follow the Makepad `script_mod!` DSL conventions of the sibling `makepad`
  checkout (`Name: value`, `name := Type{}`, `+:` merge).
