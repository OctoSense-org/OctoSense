# Daycast for OctoSense

English | [简体中文](README.zh-CN.md)

This is the OctoScript weather assistant bundle imported from the user's Daycast repository. OctoSense includes it as a desktop system app under the reserved `os.weather-assistant` id.

The question UI uses the host's one-shot `model.complete` service and supplies the current weather, wardrobe, preferences, family cities and locally stored schedule as context. Mode buttons let the person ask AI to add clothing, create a weather preference, add a family city, or create a schedule item. AI stages a review card first; saving requires the person to confirm. Family city names are resolved using the geocoding service before they are shown for confirmation. Create Schedule marks the next message as an explicit schedule request, so reminders such as taking medicine are treated as Daycast schedule items rather than alarm requests. The model can also suggest a free weather-appropriate time for an activity; it only enters the schedule after the person presses Confirm and Add. The app normalizes common date formats and checks for an overlap again before saving.

You can ask Daycast's assistant in its chat to add an event directly to the app's private schedule. The assistant asks for missing details, checks for a time conflict, then OctoSense shows a host approval sheet with the event's title and exact time. It saves only after approval and reports success only when the write completes. The system assistant can also add a Daycast event from the system chat, with the same approval.

The Today card uses the host's one-shot `model.complete` service to write an outing suggestion from the current city's weather, selected preferences, wardrobe and schedule. Its input includes temperature, apparent temperature, daily high and low, precipitation, and daily rain and UV forecasts. The card regenerates after a weather refresh or personal-data change and shows a labeled local reference suggestion if AI is unavailable. These inputs are sent to the person's configured model.

Wardrobe entries may include an optional home storage location and a photo taken with the in-app camera. A reduced thumbnail stays in the app's private storage and is not sent to weather or AI services. Selecting an existing image from disk is not supported by this host version.

Family reminders check the family's cities every 15 minutes while Daycast is open. The first observation establishes a baseline; subsequent rain onset, temperature changes of at least 5°C, crossing 35°C/0°C, or wind rising to 40 km/h create a weather reminder. Identical and older observations do not trigger again. The most recent 20 reminders and city baselines stay in private storage.

In My, read the joined rooms from the running, signed-in Rinx client, choose a family room, and enable Rinx reminders (off by default). The UI calls `storage.daycast.rinx.rooms`/`send`; DaycastService delegates only these two methods to the shell's `host_tools/daycast_rinx.rs`. This bridge accepts only Daycast's system/store app IDs and fixed room/text arguments. The AI bus routes to Rinx's native `list_rooms`/`send_message`; Rinx presents the destination and exact text, then sends through its Matrix SDK after the person confirms. The bridge returns the actual native result, and never reads credentials. Errors and declined sends remain retryable. A send interrupted by restarting Daycast has an unknown result and requires checking Rinx before retrying. Old drafts do not automatically send on startup or when enabling the switch. Closing Daycast stops weather checks; this is not an OS background scheduler.

Register at https://auth.matrix.rinx.chat and use https://matrix.rinx.chat as the homeserver. Invite relatives using full Matrix IDs to a joined room in Rinx. See the [Rinx guide](https://github.com/gosimfoundation/hackathon-agenticapp26/blob/main/docs/rinx-guide.md). Real-account delivery and device validation remain unverified until a person tests with their family room.
