# OctoSense 更新核心

[English](README.md) | 简体中文

`octosense-updater` 检查 OctoSense 的 GitHub 公开发行版，将验证通过的安装包下载到宿主私有存储。它不会安装、执行 shell 命令、替换正在运行的程序，也不会向应用智能体暴露更新服务。下载完成后，外壳应由用户明确点击，再打开系统安装程序。

`Client::check` 和 `Client::download` 是工作线程上的同步入口。网络操作使用私有 Tokio 运行时，取消请求能够中断停滞的网络操作；不要在 UI 事件线程直接调用。克隆的客户端共享忙碌状态。失败和取消会释放状态、移除本次未完成文件，允许重试。用户已打开的系统安装程序不受下载取消影响。

打包任务通过 `OCTOSENSE_RELEASE_TAG` 固化发行身份，例如 `desktop-v0.1.0-rc.2` 或 `home-v0.1.0-beta.2`。没有标签、空标签或无效标签均视为开发构建，不会伪造已安装版本。`BuildIdentity::default_channel` 为稳定版选择 Stable，为 RC 版选择 ReleaseCandidate，为其他预览版和开发构建选择 Preview。开发构建可查询最新发行版，但 UI 必须说明无法比较当前安装版本。更新比较不使用 Cargo 包版本。

| 通道 | 可选发行版 |
| --- | --- |
| Stable | 非草稿、GitHub 未标记预发布、语义版本为正式版 |
| ReleaseCandidate | 正式版，以及 `rc` 或 `rc.<数字>` 候选版 |
| Preview | 正式版和所有语义版本预发布版 |

选择依据语义版本先后，而不是发布时间；`rc.10` 比 `rc.2` 新，正式版又比两者新。Home 与桌面是不同产品线。安装包名称严格绑定版本和平台：macOS ARM64 DMG、Windows x64 安装 EXE、Linux x64 AppImage 或 DEB、Android ARM64 Home APK。Linux 只有在 `/usr/bin/octosense` 运行时选择 DEB；AppImage 还要求启动环境与运行文件路径一致。无法识别的手动安装布局明确显示不支持，不会悄悄更换格式。Home 不下载或替换需要特权的 Bridge APK；ROM 更新属于独立发布流程。

只有安装包 URL、GitHub SHA-256 摘要与发行版 `SHA256SUMS` 一致才会创建更新候选。校验清单自身也必须匹配 GitHub 摘要。初始 URL 固定在官方仓库的具体标签与文件名；HTTPS 重定向仅允许 GitHub 发行版 CDN 和官方仓库下载路径。不使用令牌、Cookie 或开发者可修改的下载端点。这是在信任项目 GitHub 发布渠道基础上的完整性校验，并不是独立的发布者签名。仍需要平台原生签名检查，尤其是 Android 与已安装应用的签名一致性检查。

每页元数据限制为 2 MiB，最多十页、每页一百条，检查总时限为两分钟。校验清单限制 256 KiB；桌面安装包限制 1 GiB，Android 限制 512 MiB，网络二十秒无进展或下载总计十五分钟即超时。流式下载同时检查长度和 SHA-256，通过后原子重命名私有暂存目录。每次尝试使用独立目录，失败不会覆盖已验证文件。Windows 使用宿主私有应用数据目录继承的 ACL；Unix 缓存目录必须为 0700，文件以 0600 创建。宿主负责创建父目录，更新器创建最终缓存目录。系统可清理缓存，此时用户重新下载即可。

`VerifiedArtifact` 提供只读身份与路径访问器。交给系统安装程序前，必须在工作线程调用 `revalidate()`，再次检查文件类型、目录约束、长度和 SHA-256。进程重启后不会复用持久化的信任凭据。尚未交给系统且不再需要的下载可调用 `discard()`，仅删除该安装包及其空的私有目录。系统安装程序仍可能读取文件，因此打开后不要删除。其他已完成文件保留在缓存中；进程突然退出可能留下未验证的暂存目录，它永远不会被视为可安装文件。

`check` 示例支持 `--product`、`--platform`、`--installed`、`--stable`、`--rc`、`--download`、`--cache`，输出 JSON，永远不启动安装程序；只有显式 `--download` 才下载。单元测试涵盖版本、通道与平台筛选、恶意元数据、重定向限制、摘要不一致、取消、未完成下载、重试、缓存权限，以及被修改或替换成符号链接的文件。实际执行命令和真实发行版验证结果以 PR 的验证记录为准。
