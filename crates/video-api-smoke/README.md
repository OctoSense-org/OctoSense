# Native Video script acceptance

English | [简体中文](README.zh-CN.md)

This small native host tests the real `Video::script_call` bridge with a contained
Splash app and a synthetic, silent, five-second H.264 clip in its storage jail.
It depends only on Makepad widgets and JSON; it does not load the OctoSense shell,
accounts or model providers. Its shared binary/library entry also builds an
isolated Android APK. The manifest requests no camera or microphone access.

The Python driver uses Makepad's local instrument to click script buttons in a
hidden native window. It checks prepare, advancing native frames, pause stability,
seek/resume, explicit stop, restart and native resource release after app teardown.
It checks each control's exact acknowledgment and refuses invalid numeric inputs.
Backward seeking must produce native frames near zero after playback passed two
seconds; an optimistic script position cannot satisfy that check. Containment is
checked against the live heap's storage jail and denied network host list.
The host observes platform decoder events independently of the script's status;
all playback commands originate in the Splash app, without Rust `VideoRef` calls.
The small MP4 is generated by `tools/generate-video-fixture.swift`; the driver records
its SHA-256 and the test binary's SHA-256 with private logs and frame captures.

**macOS verified on runtime `fc938badf`:** all 16 instrument checks passed; see the
[sanitized receipt](../../tools/fixtures/video-api-lab/evidence/macos-local-mp4.json).
To reproduce, build this workspace's
`octosense-video-api-smoke` binary, then run `python3 tools/test-video-api-native.py`
with `--host <binary>` and a fresh `--out <evidence-directory>`. The driver recipe
does not download dependencies, access a real media library or change an installed
app. It does not prove App Hub signed admission, network streams, audible sound,
capture, multiple concurrent app heaps or another platform's decoder. Record those
separately. Control acceptance and native completion are separate observations.

Android uses `tools/test-video-api-android.py`, with `--adb`, `--aapt2`, `--apk`,
an explicitly assigned `--serial`, and a fresh `--out` directory. **OnePlus 6,
Android 15: all 20 checks passed on runtime `7c859055`**; see the
[sanitized receipt](../../tools/fixtures/video-api-lab/evidence/oneplus6-local-mp4.json).
The APK must use
`dev.makepad.octosense.videoapilab.publicapis1`, and that package must be absent
before the run. The driver removes only the test package it installed.

The standalone Makepad HTTP instrument is unavailable on Android. Instead, this
fixture accepts bounded commands in its private directory and invokes the visible
contained buttons' original Splash callbacks with untrusted input provenance.
Native decoder events independently verify completion, including the first frame
positions after seeking. This is callback/decoder acceptance, not physical-touch
or pixel acceptance. The driver uses no global taps, OS screenshots, permission
grants, network listener, personal accounts or real media library.

The phone test exposed a legacy Android seek that resumed at 1,176 ms after a
2,000 ms request. The runtime now uses `SEEK_CLOSEST` on API 26 and newer; the
first observed resumed position was 2,050 ms, and rewind resumed at 66 ms. Older
Android versions retain a bounded legacy fallback and were not tested. Both
native players were released, with no frames after final teardown; the driver
stopped and removed its isolated test package.
