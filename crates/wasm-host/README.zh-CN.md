# OctoSense Wasm 运行时

[English](README.md) | 简体中文

`Runtime` 检查并编译应用经过验证的 Wasm 源字节，然后创建隔离的模块或组件实例。
客户代码的 ABI、允许的导入、存储和执行限制见 [Wasm 指南](../../docs/wasm.zh-CN.md)。

编译结果是可选的本地缓存，以源文件摘要和引擎兼容性哈希为键。每次缓存读取最多等待
50 毫秒。同一进程的所有运行时合计最多允许两个读取线程处于运行中，没有等待队列。
读取超时后，线程仍占用名额，直到实际读取结束；迟到的结果会被丢弃。每个编译缓存文件
最多读取 64 MiB。这是缓存优化的限制，不是对合法 Wasm 源码新增的限制。

缓存繁忙、读取过慢、文件过大或无法读取时，模块和组件都会编译经过验证的源字节，
并跳过本次加载的缓存写入，不会重写仍被阻塞读取的文件。快速确认不存在的缓存仍可
原子写入；快速读取后发现不兼容的缓存可重新编译并替换。缓存目录由宿主管理，应用包
提供的序列化编译结果不会被当作可信缓存加载。

缓存写入不再启动预热读取线程。`precompile` 与普通加载使用同一条有界读取路径。
调用期限、取消逻辑、客户代码内存限制和宿主请求期限均保持不变。源代码编译仍需要
时间；本次改动限制的是等待缓存读取的时间，不是编译或缓存写入时间。

运行时测试覆盖确定性阻塞读取、名额耗尽与释放、读取错误和大小限制、回退后的实际执行，
以及从已可快速读取的缓存反序列化并执行模块与组件。

组件发起 HTTPS 请求时，如果当前进程尚未选择 Rustls 加密提供程序，宿主会明确选择
`ring`。这样完整 shell 同时链接 `aws-lc` 时不会导致工作线程 panic；宿主已有的选择
会被保留。证书验证、信任根和请求期限均不改变。回归测试同时链接两种提供程序，
使用真实 Wasm 组件访问隔离的 TLS 测试端点，也覆盖宿主已先选择 `aws-lc` 的情况。
公网请求和完整 shell 的验收独立于该确定性测试；单元测试通过不代表这两项已通过。
