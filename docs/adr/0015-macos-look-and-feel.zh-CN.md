# ADR 0015：桌面及其应用的 Mac 外观与操作

[English](0015-macos-look-and-feel.md) | 简体中文

- 日期：2026-11-04
- 状态：进行中；下述各部分已在其分支上实现。最终得分和未达目标的部分记录在拉取请求中。
- 基于：[ADR 0004](0004-native-apps-hosting-and-peers.md)（英文）、[ADR 0005](0005-app-contract.md)（英文）、[ADR 0012](0012-app-host-api-discovery.zh-CN.md)。

## 背景

在 Mac 上，OctoSense 看起来像一个平板 Shell，窗口里装着手机应用。第一次独立评审给 Shell 和五个应用打了 69 分（满分 100）：控件按手指尺寸设计，工具栏位于标题栏下方，菜单栏不起作用，Mac 该用来源列表的地方用了卡片列表，文案也是手机式的。

同样的应用也发布到手机上，手机布局不能变动。脚本应用无法在构建时区分平台。原生应用、进程应用和脚本应用各有绘制方式，其中 App Hub 和 OctosCode 位于各自的仓库。

## 决策

### Mac 上默认使用 Mac 风格

Mac 启动时使用 `DesktopStyle::Macos` 及其深色版本。其他风格仍可选用，且不变。Mac 主题是 Makepad 主题目录（`widgets/themes/macos`、`macos-dark`）中的数据，加上 Shell 自身的窗口外框。

### 两个开关，不靠猜测

每张样式表都在 `crates/shell/src/octosense/style.rs::load_sheet` 中声明两个值：

- `theme.ui_pointer`：所有非手机风格都为真，决定是否使用指针布局。
- `theme.ui_unified`：仅 Mac 为真，决定是否使用统一工具栏。

有两种形态的应用保留两棵树 `TouchRoot` 和 `DeskRoot`，由 `ui_pointer` 选择。触屏树与手机上的完全相同，手机就是这样免受这项工作影响的。用 Rust 编写的表单用 `by(touch, pointer)` 取值。

### 统一窗口

选择加入的应用在窗口顶部 52 点高的区域绘制自己的工具栏，红绿灯按钮位于其上，不绘制标题栏。在这一区域内，应用未认领的按下会移动窗口（`MpRunViewAction::TitlePress`）。进程应用通过它最后上报的光标判断，进程内模块通过真实的命中测试判断。

### 菜单栏、程序坞和键盘

- Mac 菜单栏取代顶栏，包含应用名和“文件”“编辑”“显示”“窗口”“帮助”（`crates/shell/src/mac_menus.rs`）。
- 程序坞取代底部栏。窗口全屏时程序坞隐藏。它的图标和空白桌面都有右键菜单。Files 排在最前面，如同 Mac 的访达，启动台紧随其后。应用图标的菜单有“选项”，其中是“保留在程序坞中”（应用被保留时打勾）；对已保留但未运行的应用则是“从程序坞中移除”。保留的应用按顺序存放在 Shell 主目录的 `dock-apps` 中，在用户更改之前是新 Mac 的那一组。Files 没有“选项”，因为它从不离开程序坞。程序坞末尾始终有一条分隔线和一个废纸篓：废纸篓在 Files 中打开废纸篓文件夹，再次按下时回到那个窗口。它的菜单有“打开”和“清空废纸篓”，后者在一个 Files 窗口中询问。
- 正在运行的应用在程序坞中的菜单有“显示所有窗口”：把该应用在当前桌面上的窗口并排铺在变暗的桌面上，如同 Mac 的应用 Exposé。指针、方向键或 Tab 键为其中一个窗口加上边框并显示它的标题，点击或按 Return 把它带到最前面。全屏和隐藏的窗口不在其中。最小化的窗口在底部排成一行，上方有一条淡线，如同 Mac 的应用 Exposé；点击或按 Return 把它从程序坞取出并带到最前面。“新建窗口”只出现在能打开多个窗口的应用上。“选项”中有“登录时打开”，每个应用一个勾选，保存在 `dock-apps` 旁边的 `login-apps` 中：桌面 Shell 启动时按勾选的先后顺序打开这些应用，手机从不打开。
- 废纸篓里有东西时显示纸张。Files 用 wm_api 请求 `TrashFull` 告知这一点，Shell 只接受来自 Files 的这个请求；废纸篓为空时“清空废纸篓”为灰色。Files 清空前用访达那样的紧凑提醒框询问，图标在文字上方。
- 通知中心向下填满到程序坞的那一栏，可以滚动，带浮动滚动条。没有通知时只显示“没有通知”（No Notifications）。卡片的按钮在指针下、键盘所在的卡片上以及按下时显示，平时保留位置。同时最多显示三条横幅，其余的依次等待。折叠的通知组显示最新的一条，下面露出另外两条的边缘。展开的通知组标题直接放在桌面上，旁边是“显示较少”和一个圆形 ×，指针移上去时显示为“全部清除”。清除通知不再弹出横幅，按 Command-Z 可以找回。用户打开的通知会离开这一栏，与 Mac 上点按后的行为一致。实时卡片（例如邮件、快递和 News 摘要的卡片）以通知的样子出现，带有其应用的图标。小组件是 Mac 的小号日历（列出日历中今天剩下的事件）和指针式时钟。栏底的“编辑小组件”可以移除或放回小组件。
- Ask OctoSense 和 Ask <应用> 面板的高度由内容决定，从 240 点到程序坞上方的空间，并随对话增高。回复在指针下显示“拷贝”按钮，Shift-Command-C 拷贝最新的回复，右键点击消息会打开带“拷贝”的菜单。打开的 Shell 菜单在所有风格中（包括手机）都画在这些面板之上，因为 Mac 的状态菜单正好落在 Ask OctoSense 浮动的位置。
- “窗口”菜单和 macOS 15 一样有“填充”“居中”和“移动与调整大小”。“填充”以及“移动与调整大小”中的半屏和四分之一屏使用窗口管理器的贴靠区域，“恢复之前的大小”让窗口回到它自己的位置。“居中”把窗口按原有大小放到程序坞上方空间的正中。
- 键位与 Mac 一致：Cmd+W 在终端、浏览器和文件中关闭标签页，在其他应用中关闭窗口；Shift+Cmd+W 始终关闭窗口；Cmd+Space 打开搜索。平铺快捷键不适用，因此 Cmd 加点按和 Cmd 加滚动会传给应用。
- 用指针选择的编辑命令，作用于菜单打开前持有键盘的输入框。
- 应用用 `fn app_menus()` 向菜单栏添加菜单项和菜单，并在 `fn on_menu_command(command)` 中响应。原生应用的菜单项在 `native_rows` 中；原生模块可以用 `AppModule::menu_rows` 给出自己当前的菜单项（天气、备忘录和提醒事项显示“隐藏边栏”或“显示边栏”，计算器勾选当前模式）；进程应用用 `makepad_wm_api::menu_rows`（`WmRequest::MenuRows`，菜单项格式与 `app_menus()` 相同）发送自己的菜单项，选中的菜单项以 `WmEvent::MenuCommand` 或其快捷键回到应用。菜单项可以指定所在菜单的 `submenu`：Task 的“显示 > 更新频率”。菜单项的 Command 快捷键在该窗口中优先，但文本框用于编辑的按键除外。选择菜单项算作一次按下，可用于需要按下的服务。菜单项的格式见 `apps/README.zh-CN.md`。
- Tab 在文本框之间移动，按阅读顺序循环，并选中单行输入框中的内容。它只在同一个脚本或同一个应用的输入框之间移动。按钮和弹出菜单会被跳过，这也是 Mac 的默认行为，并适用于所有样式。`nav_group: true` 让 Tab 留在面板内；`keeps_tab: true` 标记 Tab 不会离开的编辑区。在此之前，Tab 在 Shell 中不起作用：窗口的模糊通道把控件从 Tab 遍历的树上切断了。
- 菜单栏中的网络、蓝牙、声音和电池会打开与菜单栏同一风格的菜单。菜单说明当前状态，最后一行通往 Mac 自己的相应设置面板。声音滑块在 UI 线程之外设置 Mac 的声音。“声音”菜单在“输出”下列出 Mac 的输出设备，勾选正在使用的那个，选择其他设备会把 Mac 的声音切换过去（CoreAudio，`crates/shell/src/mac_sound.rs`），与 Mac 的“声音”菜单一致；和 Mac 一样没有“静音”一行。其他风格保留各自的面板。
- 多个桌面显示为一个状态项，上面是当前桌面的编号。它的菜单列出这些桌面及其 Control 加数字的快捷键。系统标记和菜单之间不再放其他内容。其他风格仍在菜单栏上显示编号。
- 在文本框中右键点按会把键盘交给该文本框；如果指针下没有选区，就选中指针下的词语，然后打开“剪切”“拷贝”“粘贴”和“全选”。没有可操作内容的项目显示为灰色。沙盒中的进程应用无法读取剪贴板，所以由 Shell 代读（`AppToStudio::PasteClipboard`），且只在用户选择时才读取。
- 用户拖动窗口时，会在各应用所需的尺寸处停住（`apps::mac_window_minimum`），在工具栏相互重叠或首要操作被裁掉之前：大多数应用是 420×300 点，日历、邮件、App Hub 等少数应用更大。应用自己的控件仍可请求更小的尺寸，已经更小的窗口保持原样。其他风格的下限不变。
- 系统菜单（苹果菜单的位置）有“最近使用的项目”和“强制退出…”。“最近使用的项目”按从新到旧列出用户最近打开的十个应用，保存在 shell 的主目录中，并有“清除菜单”。“强制退出…”（Option-Command-Escape）列出有窗口的应用，默认选中最前面的那个，结束应用前先在表单中询问：独立进程的应用会被结束进程，进程内应用的窗口直接关闭，不再询问应用本身。
- 系统菜单和苹果菜单一样，只放系统本身的项：关于 OctoSense、系统设置…、App Hub…、软件更新…、最近使用的项目、强制退出… 和退出 OctoSense…。外观和桌面风格在系统设置的“外观”中（桌面菜单仍保留“外观”），“询问 OctoSense…”在“帮助”菜单中，也可按 F8，AI 提供方和审批从系统设置的“助手”打开。
- “帮助”菜单和 Mac 一样，最上面是搜索栏。输入文字后，列出菜单栏其他菜单中匹配的项目（子菜单项显示为“外观 ▸ 深色”），最多十二项，默认选中第一项，按 Return 即可执行；没有匹配时显示“无菜单项”（No Menu Items），按 Escape 清空搜索栏。聚焦搜索仍用 Command-空格。
- 隐藏（Command-H）把应用的窗口从桌面上收起，程序坞不会多出任何东西。“全部显示”只带回隐藏收起的窗口，用户最小化的窗口留在原处。应用的程序坞图标、Window 菜单中的窗口行，或在聚焦搜索、启动台中选择它，都会带回该应用隐藏的全部窗口；选择一个应用也会带回它最小化的窗口。
- 在 Mac 上，意外退出的应用会带走它的窗口，并由一个提醒框说明，提供“忽略”和“重新打开”。在其他桌面风格中，它的窗口保留，不再透明，并显示 `<App> quit unexpectedly` 和重新打开的方式。原始退出信息只留在日志中。
- 屏幕较小时，菜单栏按顺序让出空间：先是状态项，然后是时钟的日期，最后是靠后的菜单，其标题仍可用方向键到达。比可用空间更高的 Mac 菜单把最后几行收进“更多”。外壳窗口缩小时，完全位于桌面内的窗口会移入，必要时才缩小。这对所有浮动窗口风格生效。用户留在部分位于桌面外的窗口保持原位。
- 控制中心和聚焦位于菜单栏右端时钟旁边，顺序与 Mac 相同，屏幕变窄时也不会让出。控制中心展开一个模块面板：网络和蓝牙磁贴说明各自的状态并可打开详情，“深色模式”切换外观，“声音”带有滑块。这里没有开关网络或蓝牙的控件，因为 Mac 上的应用做不到。✦ 项无论哪个应用在前面都留在菜单栏上：前面的应用有代理时与该代理对话（Shift-F8），否则打开 Ask OctoSense（F8）。
- “编辑”菜单在“粘贴”和“全选”之间有“粘贴并匹配样式”（Option-Shift-Command-V）和“删除”，最后是“表情与符号”（Control-Command-Space），打开 Mac 的字符检视器；只有 AppKit 响应时才显示“开始听写…”。“粘贴并匹配样式”粘贴剪贴板中的文本。应用自己有同名菜单行时，无论从菜单还是用快捷键，执行的都是应用自己的那一行。
- “帮助”的搜索会指出找到的菜单行在哪里：在其标题处打开所在的菜单（子菜单也一样），高亮该行，并用 Mac 的箭头指向它。
- 菜单支持一级子菜单。上下文菜单的行（`ContextRow::with_sub`）和原生应用的菜单栏行（`MenuRow::within`）在旁边打开子菜单，可用指针、右方向键或 Return。没有标题的行是分隔线（`MenuRow::rule`），`MenuRow::command` 发送一个命名命令，模块在 `AppModule::menu_command` 中收到。菜单栏中的选择先交给最前面的原生模块，再交给进程应用和脚本应用的 `on_menu_command`。
- Image、浏览器和 Sheets 发送自己的菜单栏行，因此这些行随窗口变化：Image 的“显示”和“工具”菜单（向左旋转、向右旋转、显示检查器），浏览器的“历史记录”“显示”和“书签”（窗口自身控件变灰的地方，菜单行也变灰；与 Safari 一样，“历史记录”列出最近访问的网页，“书签”列出保存的网页，个人收藏在子菜单中），以及 Sheets 的“格式”和“表格”菜单。
- 桌面的右键菜单只有“更改墙纸…”：OctoSense 的桌面上没有文件，访达的其他行无事可做。外观在系统设置和控制中心中选择，“键盘快捷键”在“帮助”中（Command-/）。
- 经典标题栏高 28 点，与 macOS 11 以来一致，并以一条细线与窗口内容分开；Terminal 的标签栏和其设置窗口的工具栏与标题栏连成一体，不画这条线。OctoSense 风格也随之改变，因为它照着 Mac 的标题栏设计。
- “关于 OctoSense”和内置应用的“关于”以仓库 NOTICE 中的版权行结尾；App Hub 应用的“关于”没有这一行。
- 聚焦中的系统设置面板使用设置边栏中的图标和颜色；应用的预览列出种类、版本和位置（“随 OctoSense 提供”或“从 App Hub 安装”）。

### 字体

在 Mac 上，界面以 San Francisco 为首选字体，并使用其斜体和等宽字体。PingFang SC 紧随其后用于中文。这取代了 2026 年 10 月 19 日关于拉丁文字也首选 PingFang 的要求。没有 PingFang 时，中文和以前一样回退到内置字体。其他平台的字体链不变。

### 在窗口之外按下

离开焦点窗口的按下会关闭其打开的菜单：菜单栏、程序坞、经典标题栏、空白桌面都如此。进程应用会先后收到值为假和真的 `WmEvent::Focus`。模块与 Shell 共享键盘焦点，因此由 Shell 先放开再恢复。脚本菜单在键盘离开其视图时关闭。输入框保留键盘，因此“编辑 > 粘贴”仍能到达它。

在窗口内部，在打开的脚本菜单外按左键只会关闭菜单，指针下方的内容不会收到这次按下。在菜单外按右键会打开所按位置的菜单。

进程应用会在它的菜单打开时告知 Shell（`AppToStudio::MenuUp`）。菜单打开期间，在其窗口外按左键只会关闭菜单，和 Mac 一样，关闭菜单的这次按下不再传给别处：应用先放开键盘，再收到一次远离其界面的按下和松开，然后取回键盘，因此输入框仍保有键盘。窗口在收到焦点消息时才取回键盘，而不是在那次按下时：只有窗口内的按下才会交还键盘。终端自己绘制菜单，它的菜单同样会告知已打开，并在那次按下时关闭。在窗口外按右键同样会关闭菜单，并继续打开所按位置的菜单。

### 系统设置

设置过去是搜索面板里的长列表。“系统设置”（`os.settings`，`apps/settings/bundle`）是桌面样式的脚本应用，固定在 Mac 程序坞的最后，包含“通用”“外观”“助手”“键盘”四个面板，只有一个窗口；拖动窗口时宽度最小停在 600 点，侧边栏和搜索栏仍放得下。

- 它的更改只能通过只有它可以调用的 `settings.*` 方法进行（`crates/shell/src/app_settings_link.rs`）。每个方法都要求在其内容上按下，且都不响应智能体。
- 搜索面板不再更改设置。它按文字找到面板并打开，并把结果分组放在“最佳匹配”之下。
- 开启助手的命令执行仍然需要输入同样的文字，但改为在宿主绘制的面板上输入。应用只能请求显示这个面板。由 Shell 检查文字，并在原来唯一的位置生成手势（[ADR 0004](0004-native-apps-hosting-and-peers.md) 第 12 节）。
- “主题”只在绘制它的样式中列出。“桌面图片”在会绘制桌面图片的样式中列出：在 Omarchy 中换到主题的下一张图片；在 Mac 样式中可选 Abyssal Currents（随外观变化）、Tokyo Night 或四种颜色之一。选择保存在外壳的主目录中，桌面菜单的 Change Wallpaper… 会打开这里，与 Mac 相同。
- 睡眠、重新启动、锁定和注销仍然属于这台 Mac，因为 OctoSense 只是其中的一个应用。

### 脚本应用新增的能力

这些都是公开接口，在所有风格下生效。它们描述应用做什么，不扩大它能访问的范围（[ADR 0012](0012-app-host-api-discovery.zh-CN.md)，`AGENTS.md` 第 12 条）：

- 任何 `GestureView` 上的原生菜单：`menu`、`on_menu`、`menu_urls`、`open_menu()`、`menu_current`。
- `clipboard.write`：只写，最多 1 MiB，要求最近 5 秒内在应用内容上按下过，且绝不接受智能体调用。
- `settings.open`：只能打开 AI Providers，且必须在按下应用内容之后，让“没有模型”的死路有出口。
- `files.pick_photo` 的 `full_size`，以及 `files.export` 的 `bundled`：应用自己的图片素材，包括编译进 Shell 的素材。
- 键盘：`TextInput` 上的 `focus()` 和 `on_escape`；`GestureView` 上的 `on_key` 和 `focus()`，以及 `on_tap` 收到的 Command 和 Shift；滚动视图上的 `scroll_y()` 和 `set_scroll_y(y)`。按下按钮、复选框或单选按钮时，键盘仍留在通过 `on_key` 持有它的视图上。
- 共享的 `UiSearchClear`，以及 `LoadingSpinner` 中的 Mac 活动指示器。
- 共享的 `UiAlertIcon` 和 `ui_alert_icon`：由 Shell 按当前样式的外框绘制应用图标（`ReviewAppIcon`，每个 Splash 隔离环境都能用到）。没有 Shell 的宿主中没有它，`ui_alert_icon` 为 false。
- 代表整张表单输入框的字段可以用 `on_tab` 接管 Tab。`nav_group` 和 `keeps_tab` 决定 Tab 停在哪里。
- `WebReader` 上的 `open_embed` 和 `on_ready`，以及盖在它上面的面板所用的 `over_web: true`。

### 网页视图

网页视图由平台提供，盖在窗口绘制的所有内容之上。在 Mac 上，它的宿主图层带有一张位图遮罩，挖掉 Shell、菜单、表单或带 `over_web` 的面板画在它前面的部分，被挖掉的部分不接收点击。其他平台在有内容重叠时隐藏该视图。手机不统计遮挡，所以手机上的页面保持原样。桌面上打开页面时，每一帧都会遍历整棵控件树来查找这些遮挡。

### 按下与重绘

使用鼠标时，如果 `render()` 要替换的控件正被按住或拥有打开的菜单，它会等待；待处理的结果会在按下生效之前绘制。点击不会再因为结果恰好在按下和松开之间到达而消失。触屏不变。

在所有样式中，视图的 `finger_down` 和 `finger_up` 动作只来自主按键或触摸。在一行上按右键不算点按这一行：上下文菜单改为读取原始鼠标事件。

### 空闲时

进程应用空闲时，它的时钟会放慢。有任何活动时，宿主每 8 毫秒发一拍；应用 0.25 秒内没有输入、也没有新画面后，改为每 50 毫秒一拍。每一拍都会唤醒外壳里的所有控件，所以十三个打开的应用在空闲时的开销只有原来的五分之一。所有风格都如此。

### 文件面板

进程应用没有自己的窗口可以挂面板,Studio 运行时过去会直接丢弃它的 `SelectFileDialog`。现在在 Mac 上它请求外壳(`AppToStudio::OpenPanel`),如果该应用的窗口在最前面,外壳就显示 Mac 自带的面板。外壳总会回答(`StudioToApp::OpenPanelAnswer`),拒绝等同于取消。Image、PDF 和 Finance 通过这条路径打开文件。在其他系统上它们仍使用自己的打开表单,在 Mac 上测试可以传 `--open-home=<dir>` 来看到那个表单。隐藏的外壳用 `MAKEPAD_TEST_OPEN_FILE` 回答面板,所以真正的面板**未验证**。

### 沙盒应用使用 Mac 自带的面板

在 Mac 上，Sheets 通过 Mac 自带的面板打开和存储文件，位置由用户任意选择。这是一项行为变更：Sheets 过去只提供自己的表单，而且只限于它自己的文件夹。它的沙盒不变。它的清单仍然不请求文件夹之外的任何东西，这里也没有任何机制放宽沙盒。

- 进程应用请求外壳显示存储面板的方式与请求打开面板相同（`AppToStudio::SavePanel`，由 `StudioToApp::SavePanelAnswer` 回答），条件也相同：只有最前面的窗口能得到面板，拒绝等同于取消。Sheets 的面板从它自己的文件夹开始。
- 外壳自己的面板回答某个进程时，外壳记录一项授权：该进程的连接，以及用户选中的那个确切文件在那一刻的真实位置。符号链接会被解析；尚不存在的文件按其所在文件夹的真实路径定位。之后应用请求外壳读取或替换这个文件（`AppToStudio::ChosenFile`，由 `StudioToApp::ChosenFileAnswer` 回答）。其他任何路径、同一文件夹中的其他文件、文件夹本身以及其他进程的文件都会被拒绝，并给出简明的错误。不提供列目录，也不提供删除。
- 外壳整体替换文件：先在旁边写入一个隐藏文件，再把它移到原文件上，所以写入失败绝不会截断用户的文件。读写上限为 64 MiB，这些操作在外壳的 UI 线程之外进行。
- 实际读写时不再信任路径，因为选中的文件可能位于应用能改动的文件夹中。在 Unix 上，读取时不跟随符号链接打开文件，并且只有当打开的文件自身的路径（Mac 上用 `F_GETPATH`）就是选中的那个时才读取；写入时用同样的方式打开文件所在的文件夹，并在这个已打开的文件夹内创建并移动新文件。检查之后才放进来的符号链接或被移走的文件夹都会被拒绝。
- 授权只存在于外壳的内存中，只属于该进程的连接。重启、重新连接或进程结束都会使授权失效，也不会写入磁盘。
- 存储在应用自己文件夹中的文件仍是它的文稿：应用自己就能访问，下一个窗口会重新打开它。位于该文件夹之外的上一个文稿不会被重新打开，下一个窗口从新的工作簿开始。这是一个已知缺口。
- 没有 Mac 面板的地方（其他风格、手机、进程内托管、其他系统），Sheets 保留原有的打开和存储表单。打开或存储被拒绝时，它用自己的提示说明原因。在 Mac 上传 `--app-sheets` 可以看到这些表单，供测试使用。
- 隐藏的外壳用 `MAKEPAD_TEST_SAVE_DIR` 回答存储面板，用 `MAKEPAD_TEST_OPEN_FILE` 回答打开面板，所以真正的面板**未验证**。

### 记住位置的窗口

进程应用可以用三个请求调整自己的窗口。`WmRequest::Resize` 设置发出请求的进程自己窗口的内容尺寸。只有该窗口在桌面风格中浮动时才生效，结果限制在可见屏幕内，并不小于最小尺寸。`WmRequest::LaunchOrFocus` 进行与 Launch 相同的检查，不放宽任何条件。它把该应用以完全相同参数启动的窗口调到最前面，没有这样的窗口就启动一个。`WmRequest::FrameAutosave` 为窗口框架命名，框架按应用 id 和该名称保存在外壳自己位于 `OCTOSENSE_HOME` 下的状态中。窗口关闭或外壳退出时，外壳保存框架；应用再次使用该名称时，外壳把框架放回某个可见的显示器上。

Terminal 使用这三个请求。在 Mac 上，Command-, 打开一个带工具栏面板的“设置”窗口，而不是模态表单，手机仍保留表单。它的面板是“通用”和“描述文件”，与 Terminal 相同。“通用”包含不属于某个描述文件的设置：新窗口和标签页使用的描述文件、它们打开的文件夹、标签栏和其他程序的访问权限。“描述文件”列出各个描述文件并标出默认项，列表下方有 +、− 和 ⋯ 菜单，并以“文本”“窗口”“Shell”“键盘”和“高级”标签页显示所选描述文件。当前的设置文件就是默认描述文件，每个另存的描述文件有自己的文件，因此以前写入的文件仍可读取。窗口的框架会随窗口恢复。按 Command-Q 后再次打开 Terminal，会恢复原有的窗口，每个标签页回到它的文件夹，并以纯文本在新 shell 上方显示之前的内容，就像 Terminal 的“重新打开窗口时恢复文本”（默认打开，在描述文件的“窗口”标签页中）。这些文本保存在窗口文件旁边，只有所有者可读，只取回一次。颜色、正在运行的任务和分栏不会恢复，关闭窗口则会忘记该窗口及其文本。所有标签页都空闲时按 Command-Q 会直接退出，不再询问；仍有程序在运行时会先询问。

### Mac 上的小细节

- **意外退出的应用。** 在 Mac 上，无论应用运行在自己的进程里还是外壳里，它的窗口都随它关闭，并由一个提醒框显示“<应用> 意外退出。”，提供“忽略”和蓝色默认按钮“重新打开”。“重新打开”会在原来的位置打开新窗口；按 Return 重新打开，按 Escape 忽略。同一时间只显示一个提醒框，每个应用最多一个，其余依次等待（`crates/shell/src/quit_alert.rs`）。不会再有横幅重复说明。其他桌面风格保留停止的窗口，显示它的图标、同样的文字和蓝色的“重新打开”，在那里进程应用只能从这个按钮重新打开。
- **不能放大的窗口。** `apps::mac_window_fixed`（计算器和 Reference）在 macOS 风格下让绿色按钮、“缩放”和“进入全屏”变灰。拖动窗口边缘也不会改变它的大小；它自己的控件仍可请求更多空间。
- **编辑菜单跟随输入框。** 获得焦点的输入框上报 `HostedEdit`（托管通道中的 `makepad_edit`）：是否有选区、文本、撤销和重做。菜单项据此变灰。`field: false` 表示没有输入框在上报，此时菜单项保持可用，留给应用自己的编辑器。持有键盘的按钮、复选框或弹出菜单（`CxDraw::key_focus_is_control`）没有文本，与 Mac 相同：此时由应用自己的撤销、拷贝或全选执行。只因被按下才拿到键盘的视图（如画布、列表或分段控件）同样没有文本。makepad 会标记按下控件或视图时得到的键盘焦点（`Cx::set_key_focus_on_press`、`Cx::key_focus_pressed`），并在表单出现和关闭后保留这一标记。此时应用自己的编辑菜单项接收对应按键，并在编辑菜单中替代通用项；应用没有对应菜单项的按键仍然交给该控件或视图。
- **勾选有单独一列。** 菜单中只要有一行被勾选，就保留一列放勾选标记，其他行对齐。Mac 上应用的菜单里，每行文字从 19 点处开始，与 ✓ 留出间隙。弹出菜单按菜单行留出的距离向左偏移（`PopupMenu::words_inset`）；设置了 `popup_words_over` 的 `DropDown` 会让当前行的文字落在它自己的文字上。`GestureView` 弹出菜单只要知道按钮文字从哪里开始（`menu_words_at`，`UiPopup` 为 10），也会这样对齐。
- **页面内查找。** Writer 的“编辑”菜单有“查找…”（⌘F）、“查找下一个”（⌘G）和“查找上一个”（⇧⌘G）。“查找…”在格式栏下方显示查找栏；边输入边在页面上选中匹配处，不区分大小写。按 Return 或查找栏的箭头会在整篇文档中循环查找，键盘仍留在查找框里。按 Escape 或“完成”收起查找栏，键盘回到页面上的匹配处（`DocumentEditor` 的脚本方法 `find` 和 `find_done`，以及 `draft::find_all`）。
- **Writer 的大纲会折行。** 大纲里较长的标题会折到第二行，与 Pages 的目录相同，这样开头相同的标题也能区分开。
- **“批准”是一个工作表。** 在 Mac 上它以“完成”为蓝色默认按钮，没有窗口的红绿灯按钮；Escape 和 Return 的作用与“完成”相同。它是系统设置的一个页面，从该窗口的工具栏下方悬挂：从其他地方打开时（例如系统菜单或对话中的“打开设置”），会先把系统设置带到最前面并停在“助手”面板。它的时间限制用一个下拉菜单选择应用，菜单在按钮下方展开。规则以简短的标题显示，例如“Mail may send messages”，状态写在标题下方，每条规则一个按钮，另有一个 ⓘ，在其上方的工作表中打开规则详情。“关闭所有规则”位于列表下方，也就是 Mac 放“全部移除”的位置。每次按下所记录的内容不变。手机保留遮罩。
- **光标保持可见。** 桌面上可滚动的窗格会跟随获得焦点的输入框的光标，所有风格都如此（`FollowCaret`）。
- **过长的菜单。** 脚本菜单高于窗口时，两端显示箭头，所有风格都如此。悬停在箭头上会滚动，滚轮也可以。
- **工作表悬挂，遮罩统一。** 工作表紧贴工具栏（或其下方各栏）的底边悬挂，悬挂处为直角。宿主工作表、脚本应用的工作表（`ui_sheet_dim`）和原生应用的工作表用相同的黑色遮罩盖住后面的窗口：浅色外观 14%，深色外观 32%。
- **右键为目标加上边框。** Mac 主题打开 `PopupMenu.context_ring`。右键按下高度不超过 320 点的视图时，它的菜单打开期间视图带边框。左键不会。
- **应用自己的 Command-W。** 脚本应用中 `key: "cmd+W"` 且可用的菜单项接管这个按键。此时“文件”菜单的“关闭窗口”显示 Shift-Command-W。
- **破坏性提示。** “取消”为蓝色并排在最后，所以回车不会删除。
- **提醒框表明归属。** 在 Mac 上，多数应用的提醒框是 Mac 的紧凑提醒框：宽 260 点，应用的 64 点图标在上方，标题为粗体，文字居中排在下面。两个按钮并排、等宽，默认按钮在右；三个按钮，或文字放不进半个提醒框宽度的两个按钮，上下排列，默认按钮在最上面。与 AppKit 一样，最后一行不会只剩一个词。计算器、时钟、备忘录、提醒事项、天气、Files、Finance、邮件、News、照片、日历、PDF Tools、Quick Deck、Writer、AI Providers、YouTube 和 OctosCode 都使用这种提醒框；邮件发送前的审阅是同样的提醒框，宽 300 点，信件原文放在可滚动的框里。Sheets、Task 和终端的提醒框仍把 52 点的应用图标放在文字旁边。工作表上的表单没有图标。
- **工作表独占键盘。** 显示时，`Button{key_default: true}` 响应回车，`Button{key_cancel: true}` 响应 Esc。只要这样的按钮还在显示，工作表下面的内容就听不到任何按键；工作表离开后，键盘回到原先持有它的地方，除非此后已有别处要走了键盘。这种占用属于应用自己的窗口（`MpModuleView`），所以后面窗口里的工作表绝不会从前面的窗口夺走键盘。工作表叠放时，只有最前面的响应。在这样的工作表上按回车或 Esc 算作一次按下，与点按该按钮相同。工作表上的输入框在被按下或调用 `focus()` 时仍会取得键盘，并保留自己的 `on_return`。带破坏性选项的询问把两个标记都交给蓝色的“取消”。脚本工作表保留自己的绘制列表，所以多数帧不会绘制其中的按钮：保留列表的视图会替它们说明这些按钮仍在显示（`KeyButtons`）。隐藏的视图仍会把按键往下传，但其中的按钮不会响应。这样的工作表显示时，菜单栏中应用自己的项目显示为灰色，“关闭窗口”和 Command-W 也要等它离开，与 Mac 相同。菜单项发出的按键也会发出按键抬起，所以进程应用不会一直按住修饰键。
- **弹出框挂在打开它的控件上。** 日历的新建事件、提醒事项的详细信息和天气的添加位置都带箭头挂在各自的按钮上。在提醒事项的详细信息之外按下会保留已输入的内容。按钮旁没有空间或需要询问时，它们仍是工作表。
- **日历的弹出框就地编辑。** 与 Mac 的日历相同，事件弹出框没有“存储”或“取消”：按 Return、开始在另一个字段输入、使用某个控件或关闭弹出框时，字段的改动即生效；按 Escape 或在弹出框外按下会将其关闭。“+”会立即创建一个“新事件”。“编辑”>“撤销”和“重做”可撤回改动，并核对日历服务所持的版本。删除事件仍会先询问：日历服务无法完整恢复已删除的事件（会换成新的 id，其 Glance 卡片也已撤回）。
- **拥挤时段仍可浏览。** 重叠事件会挤得无法阅读时，“周”视图按连续时间段合并隐藏的事件并显示数量。点击数量会打开“日”视图；如果“日”视图也很拥挤，点击数量会打开可滚动的事件列表并定位到隐藏的事件。
- **加载状态只有一个窗格。** 备忘录、提醒事项和时钟把加载或失败显示为一个普通窗格，“重新开始”是工作表。
- **地图显示比例尺。** 地图在所有桌面风格的角落显示比例尺，倾斜时隐藏。没有指南针，因为方位信息不会传给脚本。
- **选区不因菜单栏而消失。** 在进程应用窗口之外按下时，会用一次失焦和一次聚焦关闭它打开的菜单，所以在有指针的平台上，可选择的列表只在键盘被其他内容拿走时才清除选区。PDF 的页面会发布“编辑”菜单能做什么：拷贝和全选，全选指当前可见的页面。
- **一周从系统设定的那天开始。** `local_time()` 增加了 `week_start`：在 Mac 上取自系统设置，每个进程读取一次；在其他系统上为星期一。日历的桌面网格遵循它，手机界面仍从星期一开始。设为 24 小时制的 Mac 上，只有菜单栏时钟跟随该设置，应用仍显示 12 小时制时间。
- **浏览器采用 Safari 的形态。** 在 Mac 上，它的工具栏没有菜单按钮：原来的各项都在菜单栏和页面的右键菜单中。书签和历史记录没有“完成”按钮，用返回、Escape 或打开它的菜单项收起；页眉末端有搜索栏，只保留匹配的行，没有匹配时显示“无结果”（No Results），Escape 先清空搜索。另一个标签页来到前面时，它的页面从地址栏拿走键盘，起始页则把键盘留在地址栏。其他桌面风格保留菜单按钮。
- **工具栏紧张时搜索栏会折叠。** 在 YouTube 窗口中播放视频且工具栏不足 600 点时，搜索栏折叠成放大镜按钮，和 Mac 工具栏收起放不下的搜索栏一样，让视频标题保有空间。点放大镜、“查找…”或 Command-F 都会回到列表，并让搜索栏准备好输入。
- **PDF 适合大小。** “显示 > 缩放以适合”（Zoom to Fit，Command-9）让页面适合窗口，和预览一样。窗口窄于 1080 点且打开查找时，工具栏的适合宽度、适合页面分段让位给文件名，页面的右键菜单仍保留它们。
- **快速查看浮在上方。** 在 Mac 上，对真实文件的快速查看浮在各窗口之上，不遮暗任何东西，和 Mac 一样。其他风格保留遮罩。
- **Files 的标签页数量不限**（桌面上），和访达一样；手机仍最多八个。“打开方式”列出应用的名称，默认应用排在最前。
- **图表标出数值。** Finance 的“净资产”和“报表”有一条按数值拟合、步长取整的数值轴，以账本的货币标注；有数值轴的图表不再在每根柱上标数值。
- **照片把删除的内容保留 30 天。** 侧边栏第一组以“最近删除”结尾。删除的照片离开所有相簿，在那里等待并显示剩余天数；“恢复”把它放回原处，“永久删除”会先询问。`library.json` 增加 `deleted`，没有该字段的图库视为空。
- **照片旋转照片而不改写文件。** “图像 > 逆时针旋转”（Command-R）和“顺时针旋转”（Option-Command-R）、查看器的“旋转”按钮以及照片的右键菜单，每次把照片转四分之一圈，所有显示照片的地方都会跟着转。`library.json` 增加 `turns`；照片文件从不改写，“导出”按原样写出。“简介”有“尺寸”一行；导入的照片会保存像素尺寸和字节数（`w`、`h` 和 `bytes`），此前导入的照片没有“尺寸”。
- **邮件可标记和移动。** 邮件的右键菜单有“标记为未读”或“已读”、“旗标”或“取消旗标”，以及移到其他各个邮箱；邮件服务增加 `mail.mark`，`mail.move` 增加 `target`，只有邮件本身在用户亲手按下时才能调用。“新邮件”是邮件窗口内的一个窗口，邮件再次打开时回到原来的位置，连同正在写的邮件。
- **邮件地址显示为标记。** 在 Mac 上，“收件人”或“抄送”中写完的地址会变成一个标记，显示邮件已知的姓名；字段为空时按 Backspace 删除最后一个标记。发送的内容和发送审查显示的内容仍是文本形式的地址，与以前相同，姓名从不发送。`trusted_user_input()` 和审查不变。
- **邮件可搜索所有邮箱。** 搜索时，列表工具栏下方有一栏，可选择“所有邮箱”或当前邮箱。来自其他邮箱的结果会标出所在邮箱，打开、回复、旗标、标记、移动和删除都在它自己的邮箱中进行。搜索所有邮箱时会在“收取邮件”的锁下依次同步每个邮箱。
- **邮件附件。** 邮件标题处有一个“保存…”菜单；有多个附件时按顺序编号，让同名文件也能分别选择。点击邮件中的文件名同样会打开保存面板。两种方式都沿用由宿主管理的附件提取和导出流程。
- **App Hub 说明原因。** 无法获取的应用页面会根据 App Hub 所知说明原因：需要更新版本的 OctoSense（附“软件更新…”）、与此版本不兼容、不适用于这台 Mac，或目录已不再提供。助手的工具按它们做的事描述，例如“查找信息”，依据是每个工具经过审核的风险和 Shell 是否先询问，从不显示工具 ID。App Hub 离线时，已显示过的图标保留。目录的 `published` 现在是 UTC 时间，按这台电脑的日历显示日期；只有日期的目录照原样显示，GitHub 目录仍只写日期，因为它的发布关口检查的是日期。目录的提示只出现在受它影响的页面：发现、App、搜索、应用页面，以及有可用更新时的“已安装”和“更新”。空的“已安装”或“更新”页面保留自己的空状态，“无法检查更新”自带“重试”。“更新”页面有“全部更新”，它依次打开每个应用自己的更新表单：应用能使用的内容可能随版本变化，需要逐个应用同意，所以每个应用仍要单独点一次，按“取消”会停止其余的更新。列表行的说明是发布者副标题中第一个开发者用语之前的部分，什么都不剩时才显示类别。
- **OctosCode 按 Mac 的方式询问。** 还没有对话时，窗口保留工具栏，“连接”“无法连接”和“没有模型提供方”作为工作表从工具栏下方悬挂，蓝色默认按钮响应 Return。工作表上的列表（例如“会话历史”或“模型提供方”）不再在每一行重复按钮：按下选中一行，右键打开该行的菜单，操作放在工作表底部或工具栏中。方向键、Return、Delete 和双击与 Mac 上一致，长列表的滚动区域停在完整的一行。模型以名称显示，例如“Claude 3.5 Haiku”，从不显示 ID；服务器做不到的事会说明可以怎么做。手机界面不变。
- **OctosCode 通过“显示”菜单展开和折叠。** Shell 中的 Mac 窗口在“显示”菜单提供“全部展开”和“全部折叠”，快捷键分别为 Control-Command-E 和 Control-Command-C，作用于对话中的推理和工具块；没有可折叠内容时选项不可用。手机和普通独立窗口保留对话内的操作。
- **OctosCode 确认历史更改。** 在 Mac 上，回退对话或恢复工作区快照时会显示独立的确认窗口，说明目标和影响。Return 和 Escape 都选择“取消”，只有点按执行按钮才会开始更改；回退进行时，重复确认不会再次发起请求。
- **OctosCode 设置菜单覆盖在表单上。** Mac 上的提供方、模型和路由菜单覆盖在对应字段上，不改变表单大小。勾选标记在左侧；方向键移动高亮，Return 选中，Escape 或点击菜单外关闭菜单。调整窗口大小时关闭菜单并保留表单；手机保留原来的选择页面。
- **AI 重试时会找到新模型文件。** 如果 AI 尚未启动模型，或上次搜索没有找到模型，下一次提问会重新检查本地模型文件。已成功运行的对话在出现其他文件时保留原有模型和上下文。
- **Files 标明示例数据。** 桌面版 Files 打开内存中的示例目录时，持续提示这些文件是示例且更改不会保存；浏览真实文件系统时不显示该提示。
- **斜杠补全跟随输入框。** 在 Shell 的 Mac 窗口中输入 / 时，命令建议紧贴输入框上方，宽度不超过输入框；对话不变暗，也不显示快捷键提示页脚。Command-K 仍打开独立的命令面板。
- **输入框带聚焦环。** 在 Mac 上，获得键盘的文本框在边框外显示一圈柔和的聚焦环：3 点宽，强调色半透明，圆角与输入框一致，边框本身不变色。没有边框的输入框、不能输入的输入框，以及 Sheets 的单元格编辑框（单元格的蓝色边框就是它的聚焦环）不显示聚焦环（`TextInput.focus_ring`、`draw_ring`）。紧贴输入框的父视图不会把聚焦环裁掉：`Cx2d::push_clip_outset` 允许绘制超出当前裁剪区域这么远。
- **靠近窗口顶部的弹出菜单**仍然以勾选的行盖住按钮打开。会超出窗口顶部的行被裁到菜单的向上箭头后面，随箭头再出现，就像 Mac 在屏幕边缘的做法，而不是把菜单往下移、让另一行盖住按钮。它从第一帧起就在那里：所需的第二帧用 `redraw_area_in_draw` 请求，因为绘制期间请求的重绘会被丢弃。
- **上下文菜单把暂时不能用的项变灰。** `GestureView` 的 `menu_off` 列出显示为灰色、方向键会跳过的行，就像 Mac 上没有可粘贴内容时的“粘贴”。Quick Deck 在剪贴板为空时把“粘贴”变灰。
- **Quick Deck 复制时保留样式。** 可以通过右键、“编辑”菜单和导航栏对对象剪切、复制和粘贴。复制的标题或正文保留版式赋予它的样式：deck 服务把它继承的位置、填充、线条、效果和文字格式写进副本（`keep_look`），所以粘贴到任何幻灯片上都不变。
- **软件更新把前进的一步设为默认。** 开发版本的蓝色默认按钮是“获取正式版本…”，“检查更新”是旁边的普通按钮。“手动打开安装器”这类备用方式是按钮行开头的链接，而不是又一个按钮。
- **工具栏用间距分组。** Task 和 Sheets 的工具栏用间距而不是画出的线分隔各组。Sheets 的名称框、公式栏和行列标题使用系统字体（`DataGrid.header_face`），已保存文稿的副标题不再显示内容。Task 不给数值着色，处理器核心以纯色条形显示。它的“停止进程”是只有图标的工具，指针悬停时显示名称（makepad `Tip`）；更新频率在“显示 > 更新频率”中（非常频繁、频繁、正常），与活动监视器一致；其他桌面风格仍保留工具栏里的弹出菜单。

- **隐私询问与 Mac 一致。** 摄像头、麦克风、位置以及设备日历的访问使用 Mac 的隐私提醒框：宽 300 点，应用图标在问题上方，“不允许”和“允许”并排。工作表总是在其窗口居中，并画在助手面板之上。网站更改的审阅把要发送的内容列为带标签的行，其中的机密保持隐藏，并放在完整的目标地址下面。过期的请求说明等了多久；名称表明会花钱的工具默认选“不允许”。每个回答所记录的内容不变。

### Mac 上的各个应用

以下是各应用自身的改动，都在其 Mac 树中。除非特别说明，手机和其他桌面风格保持原样。

- **Files** 有访达的各种视图：图标、列表、分栏，以及在访达放图库的位置放磁盘地图，可通过工具栏的分段控件、Command-1 到 4 和“显示”菜单切换。紧凑视图保留在其他风格中。分栏从开始浏览的位置一直排到当前显示的文件夹，每栏 240 点，后面是所选文件夹的栏或文件的预览；与访达一样，选中一个文件夹时窗口以它命名。← 和 → 在各栏之间移动，在其他栏中按下会在那里选中，在那里右键会给菜单所针对的行加上描边。边栏位置、书签或“前往”快捷键会让分栏重新开始，分栏条会滚动，使最后一栏完整可见。快速查看浮在窗口上方，带全窗口按钮。搜索有访达的范围栏：这台 Mac 或当前文件夹。标签栏横跨整个窗口。磁盘地图给每个文件夹的名称留出单独的一条（`DiskMap::group_bands`，只有 Files 打开）。
- **Finance** 可以添加账户：边栏底部的“添加账户”、“文件 > 新建账户…”和 Shift-Command-N 打开一个工作表，填写账本为账户保存的内容。示例数据提示条已删除。Image、PDF 和 Finance 共用的打开工作表会列出它打不开的文件并以灰色显示，与 Mac 自己的面板一样。
- **Route** 把在地图上选的点称为“放置的大头针”（Dropped Pin），找到路线后用路线起止的街道命名。搜索先列出附近的结果。旋转过的地图显示一个指南针，点按它可转回正北；出行方式用图标表示。
- **Image 和 PDF** 在窗口变窄时把工具栏收进 » 菜单。Image 用“向左旋转”和“向右旋转”转动视图而不改动文件，检查器（Command-I）显示名称、种类、大小和尺寸。PDF 在边栏中列出搜索结果及其页码，搜索栏写“Search”。快速查看面板有“打开方式”。
- **浏览器** 在历史记录和书签中找不到结果时显示 “No Results for “…”” 和“清除搜索”。“添加书签”可选择个人收藏或书签并保存描述，个人收藏显示在起始页上。链接的菜单有 Safari 的各行，其中包括“在新窗口中打开链接”和“拷贝电子邮件地址”。起始页的磁贴是 Safari 的字母图标：网站的首字母以白色显示在按网站主机名选定的颜色上。
- **AI Chat** 在“删除对话…”之前先询问，可用“重命名…”命名对话，模型是工具栏中的弹出菜单，选择保存在应用自己的目录中，下次启动沿用。模型可以回答后，空白状态只显示提示语。
- **PDF Tools、Quick Deck、Writer 和 AI Providers** 在工具栏中完整显示文稿名称，空间不够时先把模式收进弹出菜单。显示标签时，它们的工作表从标签栏底部垂下。下次可能打开的文件会说应用“现在读不了”，并提供“重试”；永远打不开的文件只给“好”。Writer 的标题在存储前显示“— Edited”。Quick Deck 在窗口中放映时有标题条。AI Providers 把 Web Clients… 留在工具栏中，读出模型之前呈灰色。
- **邮件和 News** 在窄窗口中先让出边栏，让邮件或文章留在列表旁边；工具栏放不下的内容收进 »。邮件的附件以图块显示，只有一个“存储…”；每个发件人都是粗体，“已发送”和“草稿”显示收件人（`mail.list` 的行带有 `to`）。邮件账户及其设置在“邮件 > 设置…”中，而不在边栏底部。空白阅读区显示“No Message Selected”或“No Story Selected”。新邮件不能添加附件：邮件的发送路径只有纯文本。
- **照片** 在交通灯旁有边栏按钮，并有“显示 > 隐藏边栏”（Control-Command-S）；图库可从工具栏和“显示”菜单切换为“年”“月”或“所有照片”（Command-1 至 Command-3）；窗口变窄时把缩放收进 »；相簿集中在“图像 > 添加到”子菜单中。
- **日历** 让重叠的事件在同一天内并排，每栏最窄 16 点，所有桌面风格都如此。事件弹出框使用日历的各行，边栏放日历列表和月历。
- **地图** 把路线画在地名下面，把地名画在地图符号上面并避开大头针，兴趣点名称的字号接近其所在街道，日常地图称为“探索”（Explore）（MapView 的 `mac_look`，由软件包根据 `ui_unified` 设置）。
- **提醒事项和备忘录。** 提醒事项的分组标题为 15 点粗体，下面是 13 点的行，每个列表的名称使用该列表的颜色。“编辑”菜单有删除、标记为已完成和旗标，“显示”菜单有显示已完成，并使用 Mac 的快捷键。备忘录有“格式”菜单（标题、小标题、正文、列表、清单和“字体”子菜单）。置顶、移到和删除位于 Mac 备忘录放它们的位置，“最近删除”的恢复和立即删除是图标工具。
- **时钟、计算器和天气。** 时钟的“显示”菜单勾选当前页面，“重复”是一周各天的菜单，计时结束时显示“Timer Done”。计算器的科学模式采用 Mac 的六列布局并带 2nd 键，按下的数字键只加深自身的颜色。天气的边栏有城市搜索，风、日出和紫外线指数磁贴分别是指南针、太阳当天的轨迹和带圆点的色阶。
- **Task** 有活动监视器的 CPU、内存、磁盘和网络标签，每个标签有自己的列，表格下方有一个带标签的面板；内存显示占用量（footprint）。没有能耗标签，网络也没有按进程的列：macOS 不向其他应用开放这两项。表格尽量保留所有列，先压缩进程名称列；“显示 > 列”和进程选项与活动监视器一致，大小的写法也一样。
- **Terminal** 的“键盘”标签是 Terminal.app 的按键与动作表：+ 和 − 添加或删除 `keybind` 行，现有的 Terminal 和 Ghostty 都能读取。新的 shell 会等待描述文件的字体（最多一秒），按该字体的网格启动，因此 zsh 的未完行标记不会折到第一个提示符上方。触屏设备在只有一个标签时也保留标签栏。
- **Sheets** 可以从单元格菜单和“表格”菜单添加、删除行和列。公式仍引用原来的单元格，被删除的单元格变成 #REF!。它有“复制工作表”、Numbers 的格式名称（包括货币和千位分隔符），以及错误单元格的红色三角形和说明错误原因的弹出框。它的工具栏没有“新建”“打开”和“存储”：这些在“文件”菜单中，与 Numbers 相同。工作表的标签位于工具栏下方的标签栏中，与 Numbers 相同；标签的菜单从指针处弹出。
- **OctosCode** 的每个询问和失败都使用同一种 Mac 提醒框。菜单使用 Mac 菜单的材质，弹出菜单盖在按钮上。服务器拒绝的新对话在对话本应开始的位置说明，并提供“重试”；服务器拒绝时，创建表单保留已输入的内容；边栏中可以直接重命名。
- **更新器和 Reference。** “手动打开安装器”是链接，没有待装的更新时“检查更新”是普通按钮。Reference 的标签是“Message:”，窗口只能改变宽度。

### 如何评判外观

`tools/app-ux/macos-rubric.json` 在验收评分表之上增加了 Mac 专属维度，`tools/app-ux/macos_score.py` 汇总评分卡。以下任何一项都会使界面不通过，无论得分多少：核心流程失败、基本控件在默认尺寸下被裁切、空白的死胡同、正常使用中出现开发者文本、脚本错误或崩溃。没有人查看过的必需状态，其所在维度上限为 0.8。作者自评不算验收，桌面上的手机预览也绝不能代替手机。

### 不变的部分

- 密码等机密仍只在宿主拥有的表单上输入，审批仍归宿主。在 Mac 上它们显示为表单，并且回车键特意不会批准，因为表单可能在有人打字时出现。
- 沙盒配置保持原样。没有网络权限的应用仍然没有，测试时也一样。
- 审批记录的内容不变，变的只是在 Mac 上显示的文字。

## 交付

Makepad 的部分是再叠加一个运行时补丁。App Hub 和 OctosCode 先在各自的仓库落地，本仓库的固定修订版随后跟进。不会发布任何 `[patch]`，也不会发布 `.sources/` 之外的路径。

## 影响

- 当某个界面的形态不同时，应用作者要写两棵树。`apps/README.zh-CN.md` 列出了相关陷阱：结尾方式不同的主体 `if … else` 会移除外层视图；`Fit` 父视图中的 `Fill` 子视图会塌缩；脚本中的 `if`/`else` 语句，如果第一个块以不留下值的语句（循环、`let` 或以 `;` 结尾的语句）结尾而 `else` 块以表达式结尾，函数会在下一条语句处停止（“pop_stack_value on empty stack”）。最后一个是 Splash 的缺陷，已为 Makepad 保留最小复现。
- Markdown 和 HTML 文本中的编号列表每一层嵌套使用同一缩进，编号右对齐在文字之前（`TextFlow::begin_ordered_list_item`）。这会影响所有风格和手机：邮件、备忘录和浏览器的阅读器都通过它绘制列表。
- 控件的 `visible` 是样式重新应用时保留的状态（`#[visible]` 字段在 `Apply::ScriptReapply` 后保留）。进程应用在 Shell 的样式到达前就建好控件树，所以依赖样式的 `visible:` 会保持第一次的值。这样的应用在样式应用时用 Rust 设置它，就像浏览器对菜单按钮所做的那样。
- 期间做出的框架修复对所有风格生效：正则表达式残留的捕获、macOS 14 上沙盒应用的首次连接被拒、滚动视图上光标卡住、进程应用的尺寸竞争、断行时的连字符和货币符号，以及 YouTube 结果页中某个字符跨过解析窗口末端时的崩溃。
- 菜单关闭规则意味着，进程应用会因一次它没有看到的按下而收到焦点变化。托管窗口会响应它，应用中的自定义菜单也可以据此关闭。
- 菜单的改动影响所有风格。`DropDown` 的菜单留在窗口内并盖住它的按钮。菜单行的勾选标记只在该行高亮时使用高亮颜色。由视图请求的弹出菜单在右边缘滑回，只有跟随指针的菜单才翻到左侧。比可用空间更高的菜单在该空间内用滚轮滚动，打开时当前行可见。被裁切的一端显示箭头，悬停在箭头上会滚动。
- 进程应用可以请求剪贴板文本（`AppToStudio::PasteClipboard`），并在 Shell 关闭它之前收到 `WmEvent::Quitting`。
- 应用的 `app_menus()` 菜单项及其快捷键只会出现在 Mac 的菜单栏中，所以应用移到那里的命令，在其他风格中必须仍留在屏幕上。Quick Deck 因此在 Mac 以外把撤销和重做留在工具栏。还有两个已知缺口：PDF Tools 在所有风格中只用一棵树，所以手机布局也随之改变（浮动的页面栏变成了工具栏上的翻页和缩放工具），而适合宽度和适合页面现在位于 Mac 的 View 菜单和阅读模式的工具栏中，因此手机或其他桌面只能在阅读模式中使用它们；AI Providers 读不出已保存的模型时，Mac 以外的桌面只显示 Try Again，要等加载成功才出现 Add Model…。

- 共享控件新增了上下文菜单的子菜单（`ContextRow::with_sub`）、勾选（`ContextRow::ticked`）和菜单的实际位置（`PopupMenu::placed_at`）；`MenuRow::within`、`rule` 和 `command` 以及 `AppModule::menu_command`；`Image.quarter_turns`；MapView 的 `mac_look`；以及磁盘地图的 `group_bands`。这些在被启用之前都关闭或不被使用，所以其他应用的绘制与以前相同。
- Shell 会说明它自己的进程绘制哪种风格（`desktop_style::set_process_style`），只用于 Mac 风格，因此进程内应用每次运行都采用 Mac 的指针和菜单惯例。OctoSense 风格在进程内仍偶然地取得答案。让它跟随自己的样式表会改变那种风格，所以留给维护者决定。
- 保存格式有所扩展。Sheets 把两种货币格式存为格式代码 `m` 和 `n`，旧版 Sheets 会把这样的文件当作损坏。浏览器的书签增加可选的 `folder` 和 `note`。AI Chat 把模型选择保存在应用的 Makepad 目录中。通知中心在 Shell 的目录中保存 `glance-widgets-off`。
- 暂未做的部分，原因见拉取请求：时钟响铃作为带“稍后提醒”和“停止”的通知，备忘录和提醒事项的打印与导出，计算器的程序员模式，Numbers 的标题行和冻结，地图的驾车、公共交通和卫星视图，邮件附件的快速查看和发送，只作用于 OctosCode 对话的配色，Image 拷贝图片，PDF 的旋转页面和显示模式，浏览器的“下载链接文件”，照片的浮动“简介”和按住 Option 点按“旋转”，以及 Task 的能耗标签。

## 这项决策的工作未验证的内容

- 实体手机。触屏树只在桌面预览中比较过。
- 真实模型、脚本化服务器之外的真实邮件服务器，以及真实的 macOS 保存面板。隐藏运行使用测试应答。
- Control 加点按作为右键。隐藏运行绕过了这段代码路径。
- 真实的打开面板和文件夹面板。隐藏运行与保存面板一样使用测试应答。
- 设置为深色或自动的 Mac。测试用的 Mac 都是浅色，隐藏的 Shell 也不跟随 Mac 的外观。
- 真实笔记本电脑的电池。隐藏运行用替身代替 `pmset`。
- 从状态菜单打开 Mac 真实的系统设置面板，以及真实改变 Mac 的声音。
- 真实屏幕上带遮罩的网页视图：被挖掉部分的真实点击、悬停和光标。其他平台在重叠时隐藏的路径。
- 在助手消息或 OctosCode 列表行上用触控板双指点按。隐藏运行用测试工具的辅助按键代替。
- App Hub 除“需要更新版本的 OctoSense”以外的原因，以及会修改内容或先询问的工具的描述。只有单元测试，没有测试目录能走到它们。屏幕上东于 UTC 的时区同样如此。
- App Hub 在有多个真实更新时的“全部更新”，以及新鲜的公共目录：测试目录只提供一个更新，而公共目录已超过新鲜期限，所以那里的每个“获取”都在等待更新的目录。
- Mac 本身重启或注销后 Terminal 恢复的文本。隐藏运行只退出并重新打开 Terminal。
- Terminal 的“描述文件”中：复制、恢复默认设置、只改大小写的重命名，以及滚动很长的描述文件列表。测试脚本不运行这些操作。
- “表情与符号”能否打开字符检视器。隐藏运行无法显示系统窗口。
- Files 在真实磁盘上的“这台 Mac”搜索和分栏视图。测试脚本浏览的是示例主目录，列出是即时的。
- Task 在 Intel Mac 上的空闲唤醒次数，以及内存压力图的黄色和红色。
- 描述文件指定默认字体以外字体的 Terminal：它的第一个窗口仍可能按内置字体的网格启动 shell。
- 在 macOS 15 或更早版本上播放 YouTube 视频。隐藏窗口只在 macOS 26 上绘制正在播放的视频，所以只在那里检查了播放。
