# 原生活动来源核验与打开提案

[English](0015-native-activity-open.md) | 简体中文

状态：拟议的核验接口。Rinx [PR 89](https://github.com/hagency-org/Rinx/pull/89)
提供通用定位卡片和 SDK 来源上下文。本提案不安装补位、不启用 Agent、不授予成员资格，也不修改外部依赖提交号。

`crates/shell/src/native_activity.rs` 绑定宿主取得的 SDK 账号与会话代次，重新读取来源事件，核对房间、事件、发送者和定位信息，检查当前来源与目标房间成员资格，再由已注册应用的权威资源适配器判断发送者能否分享该资源。排队后打开前再次核验，准备结果两分钟过期。聚焦键包含账号、代次、应用、房间与资源，重复点击聚焦同一视图，不同账号独立。

宿主在工作线程实现 `ActivityBackend`，读取 Rinx SDK 与原生应用注册表。`open_or_focus` 仅通过已有 `ModuleHost` 排队显示或聚焦经过核验的键，不加入房间、不报名、不发送、不签发授权。已有模块用 `ModuleHost::send_custom` 接收导航，重新检查权威资源；新模块使用注册的 `OpenSchema`。SDK 身份不来自反序列化的打开参数。接口不携带模型密钥、内核协议、回调 URL 或任意进程命令。

补位接入示例：`app=buwei`，资源为不透明活动编号，目标为活动房间。补位先核对活动组织者和权威状态，再显示报名；实际报名仍分别确认并进入既有执行与回执流程。采用通用载体前，现有 v2 活动协议保持兼容。

验证：便携接口测试已用 Rust 1.98 在 Windows GNU 编译运行，覆盖伪造来源、错误房间、未知版本、账号切换、同账号重新登录、成员与分享资格撤销、过期、重复聚焦和账号视图隔离。测试使用模拟 SDK 适配器，不能代替真实身份联调。桌面与手机完整 Shell 编译，以及具体 Rinx SDK/ModuleHost 适配器仍未验证。生产路由保持未接线，草稿先请求接口边界评审，再决定外部依赖更新。
