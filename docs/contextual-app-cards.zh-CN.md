# 新闻、照片、YouTube 与私有偏好

[English](contextual-app-cards.md) | 简体中文

这些卡片共用 Glance 工作区：摘要、展开卡片和原生 Card/Chat。展开保留原应用、
账号及内容上下文。打开新闻、打开照片、播放按钮都在卡片正文中。L0 模板由宿主
提供；模型负责有依据的研究、对话和选择，不把宿主模板声称为模型生成的代码。

| 应用 | 体验方法 | 真实数据与行为 |
| --- | --- | --- |
| News | 打开新闻 → Research topic → 展开 Glance 卡片 | 使用既有 octos 研究引擎，有范围限制的搜索、文章读取与模型总结；展示完整已校验摘要及引用，明确运行中、部分结果、失败状态 |
| Photos | 选择照片 → Glance → 打开照片 | UI 和服务共用 75 张**示例**照片的目录以及应用保存的相簿、收藏；不访问 Android 相册、不分析图像像素 |
| YouTube | 点击时段音乐按钮 → 展开卡片 → 播放 | 搜索真实 YouTube 视频并保留返回 ID；使用现有 WebReader，内容及平台限制仍可能阻止播放 |

在设置启用对应应用助手即可聊天。YouTube 的 **Daily music** 需主动开启，默认
按设备当前本地时区在 07:00、12:00、15:00、18:00、21:00 推荐；代理可修改时间
和搜索词。调度依赖 OctoSense 宿主正在运行，本次没有新增媒体 Android 后台任务。
重试安静且有上限；定时器不播放音频。用户主动选择优先于该时段默认推荐。
卡片重启后安静恢复，关闭和撤销关闭的状态会保留。

## 跨应用调用

用户要求时，Photos 代理可研究公共话题。它的 manifest 请求
`news.list/read/research/research_result/publish_card`；宿主准入仅允许这些名称，
即使 News 尚未打开也会加载所有者声明和执行器。中继检查同意状态、账号、共享
授权、参数及预算，News 服务从自己的资料库解析新闻，研究通过受限 toolbox
执行器运行并以 News 身份发布。Photos 不读取 News 文件，也不因此获得无限的
网络或模型权限。

News 获得 YouTube 搜索、读取、推荐、发布工具，以响应用户要求的相关音乐；
YouTube 获得 Photos 的读取、集合及发布工具，以完成用户要求的配乐照片任务。
授予 API 不等于允许代理无关地浏览私人数据。系统助手通过 `agents.ask` 委派，
各应用以自己的 peer 回答。

## 私有偏好记忆

成功的人类 Card/Chat 对话后，有预算限制的后台工作线程可让已配置的快速模型
从最新人类消息挑选简短、明确的偏好陈述。不会提交整段对话、文章或助手答复。
宿主只接受完整原文陈述，附加散列后的账号、线程来源并去重，写入前再次检查
同意状态及账号。不保存凭据、联系方式、医疗财务事实或猜测的偏好。不是每条
消息都会产生记忆；模型失败、不确定或预算不足时不写入。

只有系统会话提供 `preferences.list/forget/configure`。可向系统助手询问
“保存了哪些偏好？”、“忘记这条偏好”或“停止保存卡片聊天偏好”。忘记会使
待写入结果失效，并阻止重试恢复同一句话，但不删除原始聊天或其他内核记忆。

数据位于应用沙箱之外的 `apps/.host/system-memory/`，文件仅所有者可读。
当前固定版本的 octos Recall API 没有删除操作，因此不向 Recall 复制偏好。
系统助手个性化回答时读取这里的有效记忆，可按有关偏好组织一个有限的应用请求；
其他应用代理不能读取全局偏好列表。

## 验证与复现

使用本提交及固定的 App Hub 依赖构建两个 Shell，并在宿主设置中配置自己的模型。
仓库不包含账号、密钥、私人邮箱、个人照片或用户聊天捕获。

确定性服务、VM 和中继测试覆盖内容身份、拒绝未授权调用、L0 准入、导航、恢复
期限、关闭状态、跨时段调度、主动选择优先，以及私有记忆删除。已使用 Makepad
平台网络执行真实 YouTube 公共搜索。[原生、手机与模型验收](testing/contextual-app-cards-2026-10-06.zh-CN.md)
记录实际结果及构建身份；单元测试本身不能证明播放、键盘体验或真实模型研究已成功。
