# Host OS API status

English | [简体中文](host-os-api-status.zh-CN.md)

This page describes the **OS and public API integration** in [Desktop RC2](https://github.com/OctoSense-org/OctoSense/releases/tag/desktop-v0.1.0-rc.2). It connects existing native facilities to contained apps before adding more Rust engine APIs. The public declarations are published in [**app-contract 1.10.0**](https://crates.io/crates/octosense-app-contract/1.10.0); the installed host must also implement each requested method on that platform. Updating the SDK or installing an app does not update the host. The published Android Home beta.1 does not include this batch; the isolated OnePlus acceptance APKs are not a Home release. Source implementation, compilation, automated tests and real-device behavior are separate evidence.

## What this batch adds

| Surface | Contract and boundary | Platform scope |
| --- | --- | --- |
| Document import/export | `files.status@1`, `files.import@1`, `files.export@1`. Foreground import copies one selected document into a new app-relative file; export saves a snapshot of an app file. Requires `files` and `storage`. Scripts receive a relative path and byte count, never an OS path or provider URI. | macOS, Windows and Android have byte adapters. Desktop Linux additionally requires an installed supported dialog helper. iOS, OpenHarmony, web and direct-framebuffer Linux are unsupported by this service. |
| Binary app storage | `fs.write_bytes` accepts a typed U8 array, complementing `fs.read_bytes`. It uses the existing storage jail, quota and per-file limit; discovery identifies it as `storage.binary_write@1`. | This is app storage, not permission to write arbitrary OS paths. |
| Fresh location sample | `location.sample@1` waits for one fix within caller-specified age, accuracy and timeout bounds. `location.sample.cancel@1` cancels this app's pending samples. Existing app consent and OS authorization are required; sampling never opens permission UI. | Android and macOS. Starting a sample is foreground-only. No watch or background-location API is added. |
| External links | `LinkLabel::handle_event` checks the existing foreground prompt authority and page grant before calling native `open_url`. Contained apps may open HTTP(S) on their declared hosts; the `web` grant additionally permits public HTTPS pages. Other schemes are denied for contained apps. | Adds Windows `ShellExecuteW`, desktop Linux `xdg-open`, Android `ACTION_VIEW` through ordinary JNI, and iOS `UIApplication` opening. macOS and web already had openers. Linux requires its installed dispatcher. |
| Device calendars | `device_calendar.*` adds app/account-scoped consent, calendar selection, bounded event reads and physically reviewed writes; it is separate from `calendar.*` and `gcalendar.*`. | EventKit on macOS and CalendarProvider in Android Home. Actual OS-calendar interaction is pending; see the [device-calendar contract](../crates/shell/src/device_calendar/README.md). |
| Public Mail drafts | `mail.compose@1` and `mail.compose_status@1` keep versioned drafts for the caller's app/account. `mail.review_send@1` and the `mail.send@1` compatibility route require native review; neither gives an agent direct SMTP access. | Send review is implemented on macOS/Android. Linux/Windows can compose/read status but have no physical-send adapter. Real SMTP acceptance is unverified; see the [Mail contract](../apps/mail/host-service/README.md). |
| Photo selection and text sharing | `files.pick_photo@1` imports a signature-checked PNG/JPEG/WebP through an image-filtered document chooser; it does not grant photo-library access. `files.share@1` hands off bounded text, with no attachments. | Photo selection follows document-adapter availability. Text sharing is Android-only and reports chooser handoff, not delivery. Native chooser acceptance is pending. |
| Standalone audio | `microphone.record_start/record_status/record_stop/record_cancel@1` and `audio.play/status/stop@1` provide short, foreground-only, app-isolate-owned sessions using app storage. Recording requires the app and OS microphone grants. | macOS/Android source implementations. Real recording and playback acceptance is pending; these APIs do not add ASR/TTS or background streaming. See [audio sessions](../crates/shell/src/audio_service/README.md). |
| Video widget controls | `video.playback_controls@1` advertises the Splash `Video` widget ABI: preparation, playback, pause/resume, seek, volume/rate and state/error inspection. It is **not callable through `host.request`**. | Native macOS playback passed 16 checks; OnePlus 6 / Android 15 passed 20 callback/decoder checks. The [separate fixture](../tools/fixtures/video-api-lab/README.md) uses only a synthetic local MP4; other codecs/backends remain unverified. |

File transfers keep the whole-jail quota and 256-entry bounds. `files.import` takes a document of up to 64 MiB (16 MiB on Android, `max_import_bytes`): a worker stages it beside the jail and the UI links it in between script turns, so its bytes never pass through the script heap. Photo picks and exports keep the 1 MiB per-file bound. Import refuses overwrite and checks ownership, traversal and symlinks. With live app storage, `files.status` also reports `used_bytes` (the host's measure of the app's jail) and `quota_bytes` (the calling isolate's storage quota), so an app can show its storage use without counting its own files. Dialogs and callbacks retain the authenticated app/isolate identity; grants and lifetime are checked again on completion. Closing an app invalidates pending work, but cannot roll back an export whose native write has already started. Android document picks do not retain persistent URI grants. `files.pick_photo` adds an image-filtered document selection path, not a dedicated photo-library grant or large-blob API. Its 1 MiB bound explicitly refuses many original phone photos. See [file-transfer contract](../crates/shell/src/files_service/README.md), `FilesService::api_methods`, `Work::storage` and `handle_event` in [files_service/mod.rs](../crates/shell/src/files_service/mod.rs).

Location sampling defaults to a 10-second timeout and a maximum age of 5 seconds. Successful data includes a real timestamp in Unix seconds, `age_ms`, measured `accuracy_m`, `source: "platform"` and `freshness: "fresh"`. Android approximate permission is usable; a stricter requested accuracy can time out instead of silently upgrading permission. App closure, revocation, timeout and host backgrounding release sampling. The older Android `location.get@1` remains unchanged: `source: "last_known"`, `timestamp: null`, `freshness: "unknown"`. It must not be presented as a fresh fix. See [device contract](../crates/shell/src/platform_services/README.md), `DeviceService::api_methods`, and `location::methods` / `Options::value` in `crates/shell/src/platform_services/location.rs`.

External links use the same canonical URL for policy evaluation and OS launch. Control characters and malformed absolute URLs are refused; failures are logged without the URL. Native host callers retain valid absolute schemes. No `web.open` host-request method is introduced: this is the existing widget path, distinct from embedded browsing. Makepad source symbols: `normalize_external_url`, `LinkLabel::handle_event`, each platform's `CxOsApi::open_url`, `android_jni::to_java_open_url` and `MakepadActivity.openUrl`. Locate the pinned source and overlays through [runtime-patches.lock.json](../runtime-patches.lock.json) and [native-runtime.lock.json](../native-runtime.lock.json).

Unsupported capture backends emit `CameraCaptureResult::Failed` instead of silently ignoring the request. The current integration also adds a bounded [Windows still-capture worker](windows-camera-capture.md): nine actual-source worker tests and a Windows target typecheck passed, but no Windows camera hardware was exercised. Capture options now express intent explicitly: `capture()` saves locally; `capture({library: true})` requests gallery export and is refused on Windows. Declarations do not turn export on. Windows gallery export and video recording remain unsupported. Shared capture quota reservation is still incomplete. These checks do not validate native device callbacks, permission UI or privacy indicators.

## Existing facilities and remaining OS work

| Area | Already present | Still separate or incomplete |
| --- | --- | --- |
| Calendar | System `calendar.*`, connected `gcalendar.*` and the new OS-facing `device_calendar.*` retain separate identities and stores. | A third-party `calendar` grant still does not open the system app's service. Migrate custom OS-calendar calls to `device_calendar`; real permission, selection and event-write acceptance is pending. Recurrence/attendees are read-only in this version. |
| Camera and microphone | Per-app consent and OS permission remain separate. `CameraPreview` provides camera entry points; standalone microphone sessions now have their own service. | Android rejects camera-video recording; macOS has no camera-video recorder. OpenHarmony's recorder is a separate path. Windows still capture has source/type checks only. Audio sessions do not fill these video-recording gaps. |
| Audio and generated media | Makepad has native audio input/output, voice-input plumbing and the `Video` playback widget. `model.audio` already produces speech; `model.image`, video jobs and embeddings also exist. | Provider generation is separate from OS recording and playback. These media methods do not prove a live provider call or device playback succeeded. |
| Embedded pages and authentication | `WebReader::open_on_platform` has macOS, iOS, Android, Linux and Windows adapters. Host-owned `auth` services and provider/backend login flows already exist. | External-link repair does not replace embedded browsing or authentication. WebView availability, provider registration, redirect policy and platform login validation remain distinct requirements. Apps never receive the host's credentials. |
| Notifications and background work | `glance.publish` can request a card notification; `App::glance_notify` posts shell toasts and the Home shade. Mail/connected Gmail have specific background execution and durable event/outbox paths. | This is not a general OS alarm, push-token or arbitrary closed-app script scheduler. Background work needs a defined event contract, app authority and OS lifecycle support; a notification alone supplies none of those. |
| Clipboard and sharing | Native text editing/clipboard operations exist. Policed WebCard exposes `clipboard.write` under its own grant. The new `files.share` service exposes Android text sharing to contained apps. | General clipboard reads, attachment sharing and cross-platform share sheets remain separate. Chooser handoff is not recipient delivery; native declarations do not imply every backend implements them. |

Source entry points: [CalendarService and its owner check](../apps/calendar/host-service/src/lib.rs), [connected-account contract](../crates/oauth-service/README.md#app-facing-contract), [AuthService](../crates/oauth-service/src/host.rs), [device service](../crates/shell/src/platform_services/mod.rs), [model media contract](../apps/ai-providers/host-service/MEDIA.md), [Glance](../crates/shell/src/glance.rs), [`App::glance_notify`](../crates/shell/src/lib.rs), [mail_background](../crates/shell/src/mail_background.rs) and [connected_events](../crates/shell/src/connected_events.rs). Relevant Makepad symbols are `CameraPreview::record_start`, `WindowVoiceInput::ensure_audio_callback`, `CxMediaApi`, `Video`, `WebReader::open_on_platform`, `web_card::policed_tool_grant` and `Cx::share_text`.

Concrete submissions help identify the boundary: [CFAW News #114](https://github.com/OctoSense-org/OctoSense-App-Hub/issues/114) uses external article links; [Navigation #116](https://github.com/OctoSense-org/OctoSense-App-Hub/issues/116) needs location but also carries app/UI changes; [Muse #112](https://github.com/OctoSense-org/OctoSense-App-Hub/issues/112) uses a native EventKit companion. This batch does not make those entire submissions compatible with a stock host, and the broader remaining inventory is not a claim that each feature was requested by a contestant.

## Discovery, evidence and next steps

Apps should declare required method versions in `host_api.required`, use optional declarations for fallbacks, and inspect `runtime.list` / `runtime.describe` on the actual host. Discovery must agree with a registered implementation and supported platform. Manifest grants, per-app consent, OS permission and foreground authority remain distinct checks. The shell registers services in [`register_host_services`](../crates/shell/src/apps.rs) and dispatches native events in [`App::handle_event`](../crates/shell/src/lib.rs).

**Host API acceptance passed: Mac 30/30 and OnePlus 6 / Android 15 44/44.** Host API Lab **0.4.0** passed the 30 named OS/public-service checks (ten OS checks plus twenty Calendar/Mail/media discovery and refusal checks), and Android passed its original 14 checks as well. Mac source `53bab40f` and the Android APK production source `13e3b21a` used runtime `fc938badf`; `53bab40f` changes only test code excluded from that APK. The [Mac receipt](../tools/fixtures/host-api-lab/evidence/public-api-v0.4/macos.json) and [OnePlus receipt](../tools/fixtures/host-api-lab/evidence/public-api-v0.4/oneplus6.json) bind each result to actual source, runtime and artifact hashes. Mac also verified signed tool completion, live UI updates and native button interaction; three captures were inspected and both owned processes exited cleanly. The Android fixture was force-stopped after completion.

The separate [regression receipt](../tools/fixtures/host-api-lab/evidence/public-api-v0.4/regression.json) records **1,051/1,051 shared-shell tests, zero failures or ignored tests**, three packaging checks and the native fixture build at `53bab40f`. Earlier 14- and 24-check records remain historical evidence. These receipts do not validate later Android Video Java changes, real Calendar event reads/writes, SMTP delivery, physical permission approval, audio capture/playback or native file/photo/share choosers. These receipts predate the release candidate and do not validate its final packaged binaries.

`runtime.describe` for `video.playback_controls` reports `kind: "runtime-abi"` and `callable_via_host_request: false`; invoke the documented methods on a `Video` widget. The separate Video acceptance passed all 16 native macOS checks on runtime `fc938badf`; [receipt](../tools/fixtures/video-api-lab/evidence/macos-local-mp4.json). OnePlus 6 / Android 15 passed all 20 callback/decoder checks at source `942fe1da`, runtime `7c859055`; [receipt](../tools/fixtures/video-api-lab/evidence/oneplus6-local-mp4.json). The phone run verified the Android nearest-frame seek fix, native stop/restart and player teardown; it did not verify physical touch or Android pixels. Its five-second silent local H.264 clip cannot establish streaming, audible output or codec breadth. Network Video sources currently check the initial URL only: redirect and nested HLS/playlist allowlist enforcement remains an explicit gap, so this batch does not claim complete contained-network policy for those paths.

For declarations, use `requires: ["host-api-v1"]` and exact method/ABI major versions in `host_api.required`, not a `host-api-v1.10` feature string. Contract 1.10 is the SDK version; availability still comes from the installed host and its platform adapters.

After these OS boundaries, the next work is **public Rust-backed image and spreadsheet APIs**. Existing [`PhotoService`](../apps/photo/host-service/src/lib.rs) and [`SheetsService`](../apps/sheets/host-service/src/lib.rs) already wrap native Rust engines, but their system/native-app gates and shared engine state are not a public per-app contract. Public adapters need executable discovery schemas, app-owned files/handles, quotas, bounded asynchronous jobs, cancellation and lifetime checks before opening access. Spreadsheet support is an explicit product priority; optional photo/OCR ideas are not established blockers for every submitted app. New wrappers should reuse the Rust engines rather than reimplement them in script.

JNI-like **dynamic native-library plugins are deferred**. Ordinary JNI calls that wire Android OS APIs are part of the current implementation. A future native-pack loader needs its own ABI, trust and isolation design; it is not a prerequisite for these shared services.
