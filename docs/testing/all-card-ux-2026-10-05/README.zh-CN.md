# 全卡片手机 UX 验收 — 2026-10-05

[English](README.md) | 简体中文

本次覆盖手机当前系统应用目录中全部 Glance 发布者：**邮件、日历、新闻、
照片、地图、相机、YouTube**，以及 Android 上 DeepSeek、MiniMax 编写的
两组六类模板，包含无特权财经原型。AI Providers 没有卡片，不适用。本次不是
对所有原生应用、第三方安装包或外部业务 API 的全面验收。

指定的 OnePlus 6 使用独立 Lab 测试包 `2026100501`–`2026100504`，基于
`a2a0524d` 加本次修改。[构建记录](builds.json)包含 APK 与源码哈希。
所有卡片数据均为虚构；没有替换已安装的 Home 或用户 Gmail 测试包。
ADB 执行操作并截取真实屏幕；Makepad 无窗口测试验证实际布局几何。
本轮**没有**运行新的 Studio Instrument 会话。

## 覆盖与结论

共 **33 种输入配置**：九个产品通知／事件／议程场景、12 份模型 L0 源码、
12 份模型 Splash 程序。浅色交互与深色初始渲染分别检查，不是 66 项完整业务
端到端测试。详见[逐项结果](results.json)和[截图浏览页](index.html)。

| 发布者／类型 | 实际操作 | 边界 |
| --- | --- | --- |
| 邮件 | 产品通知、两组回复视图、生成编辑器与键盘、本地草稿保留、宿主 Card/Chat | 模型 Send/Queue 是演示；权威 Email/Chat 需要单独绑定宿主草稿 |
| 日历 | 长日期／地点／备注、三条议程、空议程、两组 RSVP 和列表 | 本地 RSVP 不发送邀请答复 |
| 新闻 | 长通知、两组 Save、文章／列表、拒绝助手状态 | 未验证实时抓取或后端书签 |
| 照片 | 长通知、两组 Favorite、元数据／列表 | 未验证照片库接入 |
| 地图 | 中英文长通知、原生 Chat 输入、键盘和收起恢复 | 未验证导航或路线效果 |
| 相机 | 中英文长通知、首次助手同意、原生 Chat 输入与保留 | 未验证拍照 |
| YouTube | 长通知、两组 Watch later 和列表 | 未验证播放或远端播放列表 |
| 财经原型 | 两组 Watch 和列表；没有凭空出现 Chat | `test.finance` 没有应用 Agent 或业务权限 |

两组 L0 均完成本地操作、收起恢复，以及同意权限允许时的原生输入框检查。
两组 Splash 均打开了 L0/L1/L2 视图。DeepSeek 的 Loading/Empty/Error/Ready
状态按钮已实际操作；MiniMax 没有对应的生命周期切换按钮，不计入这项通过。
完整 Splash 程序以卡片发布方式加载，源码保留；此路径不验证安装包、资源加载
或 App Hub 准入。

## 发现与修复

| 问题 | 修改与证据 |
| --- | --- |
| 全高 `Fill` 根视图位于 `Fit` 包装内时显示空白 | 宿主分配实际工作区高度；自然高度的 L0 继续使用外层滚动。12 份 Splash 均已在手机显示。 |
| 部分完整程序超过原先共用的 16 KiB 限制 | L0 仍限 16 KiB，Splash 单独限 64 KiB；测试准确边界通过与超限拒绝。 |
| 日历长元数据挤掉标题，空议程仍有空行 | 标题和元数据纵向排列并限制宽度，省略不存在的事件和空末尾摘要。 |
| 日历长日期被半宽方块截断 | 改为全宽日期／时间标签行；长备注可滚动。 |
| DeepSeek 照片／视频／新闻说明被截断 | Android DeepSeek 看截图后，在六类模板的说明文字中自行添加换行宽度。 |
| 内部滚动区的回复编辑器被键盘挡住 | 宿主从内到外调整焦点所属的真实滚动容器；编辑器和后续控件滚入视口，手动阅读不会持续被拉回。 |
| MiniMax 邮件 L1 Reply 不显示编辑器 | Android MiniMax 自行修正 `do_reply`，先选择 L2 父视图，再显示回复路由；已补测键盘和收起恢复。 |
| DeepSeek 六个完整应用的导航字体继承宿主设置，States 被截断 | 第一次模型修改仍截断；第二次截图反馈后，模型改为 11 点字体和较紧内边距，保留 44 点高度，六个手机截图通过复查。 |

模型源码修改（包括 DeepSeek 导航字体复查）的成功工具记录、原始／输出哈希
及重放验证，保存在 [App Design Flow PR #146](https://github.com/OctoSense-org/OctoScript-App-Design-Flow/pull/146)。
操作员提供截图与反馈，没有手改生成源码。两种模型使用既有配置，关闭备用模型，
ledger 终结消息确认实际服务商和模型。

初次脚本中存在尚未进入 MiniMax 详情就查找按钮、过早截图、Ready/Open app
名称重复等操作问题。失败记录仍保留在本地证据中，改进等待和选择器后的复测单独
记录；不把这些问题当作产品缺陷，也不冒充首次运行成功。
最后一轮说明修正还遇到锁屏后 Lab 后台网络受限；唤醒手机并恢复前台后，
同一 DeepSeek 配置成功完成其余四份源码的修改。

## 检查与复现

连续使用六张卡片后逐一返回，五个本地选项和邮件未发送的宿主聊天文字均保留，
超过三个干净工作区的缓存上限。新闻既测试原有拒绝状态，也在隔离 Lab 中通过
原生首次 Allow 面板启用，输入框可以输入并在收起后保留；随后恢复原 Lab 同意文件。

12 次交替 600 毫秒的 Glance 拖动中，同一 Down/Up 触摸内的 416 个连续 CPU
帧标记间隔，中位数 **16.74 毫秒**、p95 **17.72 毫秒**、最大 **36.57 毫秒**，
九次超过 25 毫秒。[原始与分段指标](performance.json)同时保留未分段数据；
它包含 ADB 手势之间的停顿，不能称为连续滚动延迟。这些指标排除松手后的惯性
滚动，也不代表触摸到显示的延迟。

另三次 SurfaceFlinger 采样在标记的活动区间测得 **56.9–59.7 fps**，最大显示
帧间隔分别为 **16.77、33.50、33.48 毫秒**。报告单独保留包含空闲时段的统计；
输入后的第一帧不等于可见内容的响应延迟，本次滚动没有单独的状态响应标记。

已执行 **924 项共享 Shell 测试**、三项日历服务测试、桌面默认与 mobile-apps
检查、手机 mobile-apps 检查、两种 Shell 依赖图和运行时固定版本验证。
新增 Makepad 绘制回归覆盖全高根视图、键盘高度变化、内部编辑器与操作按钮的
位置、文字保留，以及手动滚动不被拉回。

[`tools/card-workspace-fixtures.py`](../../../tools/card-workspace-fixtures.py)
导出虚构输入与源码哈希，供开发入口 `glance-fixtures:<path>` 使用。已实际执行
产品议程导出和修正后 DeepSeek 照片原字节导出。模型场景需要指定归档的
continuations 目录、模型、语法；可通过 `--source` 选择模型输出的替代文件。
工具不会操作手机或宣称验收通过，发布者仍需通过正常权限检查。

## 不计入通过的范围

这是有明确边界的工作区验收，**不是 9/10 产品 UX 签收**。原型评审导航仍与
原生 Email/Chat 风格不同。模型源码在深色宿主中仍绘制自己的浅色表面；文字可读
不代表适配了完整深色设计。MiniMax 固定头部和底部在键盘弹出时留下较小的回复
区域，编辑器可用，但审核操作可能需要滚动或收起键盘。这些视觉局限不能靠加分
掩盖。

本轮不宣称新一轮盲测邮件触发、SMTP 发送、真实 RSVP、路线规划、拍照、照片库、
播放、实时行情、完整中文本地化、横屏、屏幕阅读器或大字体验收通过。
既有真实 Mail 和模型测试另见[组合邮件卡片](../../mail-composable-cards.zh-CN.md)。
真实邮件发送仍要求用户实体批准，本轮没有执行。
