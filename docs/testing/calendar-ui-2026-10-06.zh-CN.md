# Calendar 应用与 Glance 验证 — 2026-10-05–06

[English](calendar-ui-2026-10-06.md) | 简体中文

此前 Calendar 界面只显示说明，没有呈现已保存的日程。Mail 虽能调用 Calendar
工具预订时间，用户却看不到日期标记。现在 Calendar 的月历、每日列表、详情和编辑
都使用同一个宿主管理的日程存储，并继续使用应用原有的日程卡片模板。卡片顶部的
“Open Calendar”通过 `event/<id>` 打开真实 Calendar 应用中的同一条日程，
不会另建日程或独立的卡片数据库。

这是[先前 Mail→Calendar 实机验证](mail-calendar-2026-10-05.zh-CN.md)的后续。
原报告保留了当时重复通知、重启丢失卡片的观察。本次增加已保存日程的持久化发布
记录：相同且仍有效的发布重试复用卡片，不再通知；编辑安静刷新卡片；重启恢复原
发布时间和过期时间。关闭卡片和撤销关闭会持久化，删除日程会撤下其卡片。
临时通知和议程卡片不属于本次恢复范围。

## 原生界面验收

Codex 编写并驱动本次实现，使用 Makepad 原生远程仪器，在自己启动的隐藏 release
Home 实例中验证。窗口逻辑尺寸为 412 × 892，日程和发布记录均为隔离存储中的虚构
数据。检查包括真实像素和保存后的数据，不仅依赖工具返回消息。

- 月历标记 10 月 6 日，每日列表分别显示两条日程及各自时间。
- 已保存日程可打开详情，发布仍使用 Calendar 原有模板。
- 修改配送测试日程后，原 id 不变，对应卡片同步更新。最终 Glance 和跳转后的
  Calendar 详情均显示 **11:30 PDT**。
- 重启恢复卡片且不重放通知；“Open Calendar”定位到真实应用中的同一条日程，
  编辑器显示保存的时间。
- 空标题保存不修改存储，错误提示位于表单上方。可以在界面中新建和删除临时日程，
  删除需要再次确认。
- 编辑器可滚动，未知结束时间保持空白，日期、时间和时区分别输入。只有日期的输入
  在现有后端中规范化为午夜，并非单独的“全天日程”模式。

早期迭代暴露了返回对象缺少可选字段、校验提示超出可见区域的问题，已修复并复查。

## 范围

这是 OctoSense 的本地 Calendar，不包含 Google Calendar 同步、邀请邮件或提醒闹钟。
Mail 以自己的身份调用 Calendar 已准入的工具，不获得 Calendar 界面能力或原始目录
访问权。编辑携带期望的已保存快照，过时写入会被拒绝。更新工具属于 Calendar 自己的
代理，没有新增授权给 Mail 或系统代理。

本次后续验证没有覆盖手机键盘修改操作、无障碍、多日历布局、后台作业发布 Calendar
卡片，以及新的模型基准。没有给出数字 UX 评分，也没有宣称完整日程产品已验收。
