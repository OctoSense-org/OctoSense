# OctoSense Photos Implementation Plan

> **For Codex:** Execute this plan task by task in this session; the user has authorized implementation and connected-device validation.

**Goal:** A working Apple Photos-inspired app in OctoSense-mobile, using bundled sample photography and the user's generated family portraits.

**Architecture:** Add `apps/photos` as a local AppModule with ID `photos`, replacing the upstream picture wall in the existing launcher. Use shared Makepad/OctoSense widgets and the Octoscript UI kit (`KitBottomNavigation`, native `Image`, `PortalList`, inputs and buttons) for declarative composition. Rust owns a small catalog, navigation, slideshow state, and persistent albums/favorites.

**Tech stack:** Current pinned Makepad runtime, Splash/Octoscript `script_mod!`, Rust, serde JSON, Android/ADB.

## Scope agreed with the user

- Sample photos plus `scripts/individuals`; future photos should be easy to add.
- Library and Collections, viewer, editable albums, generated Memories.
- Validate on the connected OnePlus 6T, not merely on desktop.
- No camera/media permissions, cloud sync, facial recognition, or photo editing in this milestone.

## Design

Visual thesis: a quiet white canvas, strong headings, blue controls, and rounded photographic collections, with dense edge-to-edge grids and immersive dark viewing.

Content: Collections (default) shows Memories, Albums, People, and Favorites; Library shows all catalog images in date order. Albums can be created, renamed, edited, and deleted without deleting photos. Memories derive deterministically from catalog date/place/event metadata and play as timed slideshows. Search filters available metadata.

Interaction thesis: native scroll momentum, responsive selection feedback and tab state, swipe navigation in the viewer, and slideshow progress. Touch targets remain at least 44 logical pixels.

Reuse decisions: the shared kit supplies semantic navigation and the native widgets supply images, list virtualization, text entry, and actions. The upstream Photos app is useful for AppModule integration, but its comic-tile store is unrelated to this catalog. Hosting the complete AI AppCard composer would add an unrelated kernel/transport requirement. No framework checkout changes are planned.

## Task 1 — Model and persistence

- Create `apps/photos/Cargo.toml`, `src/lib.rs`, `src/model.rs`, `tests/library.rs`.
- Add meaningful tests for album validation/edit/delete, favorite round trips, deterministic memories, missing IDs, and catalog search.
- Run `cargo test -p octosense-photos --test library` before and after implementing behavior.
- Persist schema-versioned JSON atomically under the platform app data directory; expose read/write failures without destroying unreadable data.

## Task 2 — Bundled imagery

- Create `apps/photos/resources/catalog.json` and `resources/photos/`.
- Preserve originals in `scripts/`; copy portraits and the group image into the app. Add a modest set of locally bundled landscape/nature photos with source provenance.
- Use stable photo IDs and metadata, with compile-time inclusion for Android offline availability.
- Document adding a catalog entry and rebuilding.

## Task 3 — Native UI

- Create `src/ui.rs` (Octoscript widget composition), `src/view.rs` (controller), and `src/main.rs` (standalone development entry).
- Build Collections, Library/grid, album editor, metadata search, viewer, favorites, People, and memory playback.
- Use PortalList reuse and cached native image textures, with no network dependency for browsing.
- Keep selected album membership as a draft until Save; Cancel discards it.

## Task 4 — Shell integration

- Change the root manifest's `app-photos` feature and mobile dependency to the local crate.
- Update `src/apps.rs` and `config/apps.json` while preserving the `photos` launcher identity/icon.
- Run local model tests, `cargo check --features mobile-only,app-photos`, and the relevant registry tests.

## Task 5 — Device validation

- Build the existing Android shell with the installed cargo-makepad toolchain.
- Install the updated APK without clearing application data. Launch and open Photos.
- Exercise tabs, scroll, viewer next/previous, favorite, search, album create/rename/membership/cancel/delete, memory playback, and persistence after restart.
- Capture and inspect native app frames. Fix visual/input issues and rerun affected checks.
- Record evidence and exact build/run steps in `docs/photos.md` and `progress.md`.

## Acceptance

The Photos launcher opens the local app on the phone; each visible control performs its stated action; all bundled photos load offline; albums and favorites survive a restart; Memories are computed from the catalog; changes remain reviewable in the workspace.
