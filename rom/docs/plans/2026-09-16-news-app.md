# News App Implementation Plan

> Execute task by task; each task lists its files, tests and commands, and the
> "Accepted changes" sections record where the code deliberately differs.

**Goal:** A News app crate at `apps/news` that aggregates Hacker News, TechMeme, Google News and the person's own RSS/Atom feeds into a tabbed view, runs standalone, as a process-hosted tile, and as an in-process `AppModule` with a wide phone home tile.

**Architecture:** One crate mirroring the framework's Weather app: a library with the model (pure Rust, unit-tested), two parsers (RSS/Atom, Algolia JSON), a `NewsView` widget with a full face and a tile face behind a `HostedView`, an `AppModule` implementation, and one assistant tool; plus a thin standalone binary. All network goes through `cx.http_request` and arrives on `Event::NetworkResponses`; persistence goes through the instance's `StorageHandle`. The host links it behind an `app-news` feature (mobile links it unconditionally) and lists it in both catalogs and the phone home tiles.

**Tech Stack:** Rust 2021, Makepad at the pinned fork revision `ad8f3729d2c24ba5a3bda5c8865a2b8366480147` (`makepad-widgets`, `makepad-app-module`, `makepad-wm-theme`, `makepad-wm-api`, `makepad-ai-services`), `makepad_micro_serde` for JSON. No new external crates.

### Accepted changes from the review after Tasks 1–3

The code quality review of Tasks 1–3 found a quadratic entity scan and
overflow panics; the fixes below were authorised and supersede the plan text
where they differ:

- The expected unix timestamps in the Task 2 tests were wrong by one day in
  this plan; the tests use the Python-verified values (2026-09-16T12:15:01Z
  is `1_789_560_901`).
- `strip_tags` classifies known HTML tags (inline dropped, block to a space)
  and keeps unknown `<...>` text literally, so titles with literal angle
  brackets survive.
- `decode_entities` bounds the `;` scan (linear time); numeric entities
  reject signs and control characters other than tab, newline, CR.
- Date parsers validate ranges (`unix_seconds`, `hms`); a zone-less RFC 3339
  time is UTC.
- `truncate` returns at most `max` characters, trimmed, then `…`; the test
  expects `"héll…"` for `truncate("héllo wörld", 5)`.
- `clean_text` strips CDATA markers anywhere in the text.
- Feed type is detected from the root element (BOM, PI, comments, DOCTYPE
  skipped), falling back to the `<item`/`<entry` heuristic; `<atom:entry>`
  feeds are normalised; an empty valid feed is `Ok(vec![])` and `parse_body`
  turns zero rows into the error.
- `parse_item`, `split_google_source`, `rss_link` (with a permalink-guid
  fallback and the http filter inside), `element` returning `(attrs, text)`,
  `content:encoded` as a summary fallback.
- Helpers other than `parse` are `pub(crate)`.
- `hn.rs` uses `#[rename(objectID)] object_id`, extracts `row(hit)`, skips a
  hit with nowhere to link, and omits the discussion line when there is no id.
- `parse_user_feeds` trims label and url.

### Accepted changes from the review after Tasks 4–5

These supersede the Task 4–5 text where they differ; Tasks 6–11 build on
this contract:

- `SourceState` has `attempted_at`; `due` waits `REFRESH_EVERY` after the
  most recent attempt or success (`fetched_at.max(attempted_at)`), so a
  failing source is not refetched every tick. A manual refresh calls the
  fetch directly. Cancelling (`cancel_all`, the user-feed drain) clears
  `attempted_at` with `pending`.
- User-feed ids are `user_{:016x}` of `LiveId::from_str(url)`, so cache keys
  follow the URL, not the position. `set_user_feeds` returns
  `(Range<usize>, Vec<LiveId>)`: the added indices and the pending ids of
  removed user feeds, which the view cancels. It dedupes by trimmed URL
  (first wins, cap applied after dedupe) and closes the open row whenever a
  user tab is selected.
- `relative_time` uses `saturating_sub`; `hn.rs` accepts `created_at_i` only
  in `0 < t < 1e11`.
- `host_of` strips userinfo and a port, keeps IPv6 brackets, matches `www.`
  case-insensitively, and falls back to the trimmed input.
- `ai::answer`: empty args mean everything; unparsable args, an unknown tool
  and an unknown source are `ToolResult::refused`. An empty tab answers the
  status alone (`NO_HEADLINES`) or `No headlines: <status>`.
- `row_count(tab)`, `plural(n, noun)` (`1 point`, `2 comments`), `load_cache`
  drops rows without a title or an http(s) link and caps at
  `MAX_ROWS_PER_SOURCE`, `source_index` matches ids before labels.
- Task 6's view: tabs are set with `set_active(cx, i == tab, Animate::No)`
  (`select` re-emits a click); row taps use
  `item.as_view().finger_up(actions).is_some_and(|up| up.was_tap())`
  because an empty-path `view(cx, &[])` lookup returns an empty ref at this
  revision; after the feeds file loads the view fetches the current tab's
  due sources.

### Accepted changes from the review after Tasks 6–7

These supersede the Task 6–7 text where they differ:

- `NewsView::set_storage(&mut self, cx: &mut Cx, storage)` is call-once; a
  handle that arrives after `ensure_started` triggers the feeds and cache
  loads at once (`load_from`). The module passes `vm.cx_mut()`; the
  standalone window sets storage before dispatching the `--tile` event.
- The open row is tracked by link: `NewsModel::expanded: Option<String>`,
  `toggle_expanded(&str)`, `is_expanded(&str)`, so a refresh that reorders
  rows keeps the same story open.
- `parse_user_feeds` dedupes by trimmed URL before the cap (superseded: see
  the final review section; `set_user_feeds` owns it now).
- `tile_line(&Headline)` lives in `model.rs`; `NO_HEADLINES`, `age`,
  `plural` are `pub(crate)`.
- The view tracks cache writes and logs storage read and write failures;
  `apply_feeds_file` is extracted from `on_storage`.
- `HttpRequest.max_response_body_bytes` is set to `MAX_BODY_BYTES`.
- `render` scrolls to the top when a refresh shrinks the list past the
  first visible row; tab switches use `set_first_id_and_scroll(0, 0.0)`.
- The short-tile check ignores a zero-height first frame; `SHORT_TILE` is
  96 and the tile padding 10.
- The `Muted` text role is `theme.color_text_meta` (the disabled role is
  nearly invisible on the dark app background).
- The design document's mention of a `standalone` Cargo feature does not
  apply: the crate has no features, like Reference; the binary always builds.

### Accepted changes from the review after Tasks 8–9

- The standalone window opens its `AiServicePort` only when hosted
  (`cx.in_makepad_studio()`): without an in-window assistant a parked link
  would queue context frames forever.
- `ai::answer_root(root, call)` answers on a `WidgetRef` and is shared by
  the module executor and the standalone window.
- `set_storage` logs when called twice.
- `mobile_tiles::home_layout_for_apps` caps the banner height so one row of
  favorites always fits: `wide_h = min(s * 0.55, floor(room / banners))`,
  never below 60. `FAVORITES_CELL_MIN = 88` is a named constant. Two banners
  are pixel-identical to before; three banners on Android's real home top
  shrink to fit. A test pins a height where rounding would have broken it.

### Accepted changes from the final whole-feature review

- `atom_link` advances past each scanned tag (linear time), with a wall test.
- `is_http_url` (case-insensitive `http://`/`https://`) is the one link check
  in `feed.rs`, `hn.rs`, `showable` and `parse_user_feeds`.
- `body_text(status, body)` owns the network trust boundary (200 only, a
  body, under `MAX_BODY_BYTES`, UTF-8) and is tested; the view calls it.
- `set_user_feeds` alone dedupes and caps user feeds; `parse_user_feeds`
  only parses, trims and drops non-http entries.
- `due_at`, `status_text_at`, `age_at` take a `now: Instant` so the tests
  move the clock instead of depending on machine uptime.
- `HN_LABEL` holds the "Hacker News" label once.
- Docs say the open-URL call works on macOS and web and is a stub on Linux,
  Android and iOS; NEWS-01 covers all three. The unrelated README sentence
  about the menu chord was dropped; News is the third in-repo app.
- The plan text was trimmed to this summary once the code existed.
