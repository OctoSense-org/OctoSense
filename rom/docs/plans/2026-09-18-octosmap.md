# OctosMap Implementation Plan

> Execute task by task; each task lists its files, tests and commands, and the
> "Accepted changes" sections record where the code deliberately differs.

**Goal:** A maps app crate at `apps/maps` with the interface of Google Maps: a full-screen map under a search bar, a place sheet, directions by car, foot and bike, and turn-by-turn navigation with a simulated drive; it runs standalone, as a process-hosted tile, and as an in-process `AppModule` the phone links.

**Architecture:** One crate in News' shape. Pure Rust modules, unit-tested without a window, hold everything that is not drawing: geometry and text (`geo`), the Photon and OSRM parsers (`places`, `routing`), guidance over the framework's `NavSession` (`guidance`), the sheet's detents (`sheet`) and the screen state machine with its request bookkeeping (`model`). One widget, `MapsView`, owns a persistent `MapView` and a layer per screen over it. All network goes through `cx.http_request` and arrives on `Event::NetworkResponses`; location arrives on `Event::LocationUpdate`; persistence goes through the instance's `StorageHandle`. The host links it behind an `app-maps` feature (mobile links it unconditionally) and lists it in both catalogs and the app library.

**Tech Stack:** Rust 2021, Makepad at the pinned fork revision `45d541339749f3ef109c9b226cc21238d6b6071a` (`makepad-widgets` with `maps`, `makepad-app-module`, `makepad-wm-theme`, `makepad-wm-api`, `makepad-map-nav`), `makepad_micro_serde` for JSON. No new external crates.

**Design document:** `docs/plans/2026-09-18-octosmap-design.md`. Read it first.

**Reference code (read before each task; it is the ground truth for API names):**
- The route app: `../makepad/apps/route/src/{view.rs,chrome.rs,nav.rs,module.rs}`. `chrome.rs:193-211` declares the `MapView`; `view.rs:300-380` is the location state machine; `view.rs:640-700` starts, stops and applies a navigation tick; `nav.rs` is `ActiveNav` and the simulated drive.
- The map widget: `../makepad/widgets/src/map/view.rs` (`MapViewAction` at 3038-3072, the setters at 11106-12016, the `MapViewRef` readers at 12018-12280, `TileSourceConfig` at 310-450) and `map/overlay.rs:482-533` (`MapMarker`, `MapPuck`).
- The navigation session: `../makepad/libs/map_nav/src/{nav.rs,graph.rs,geo.rs}`.
- The in-repo template for everything else: `apps/news/src/{view.rs,model.rs,module.rs,main.rs,test_support.rs,hn.rs}`.
- Host: `src/apps.rs`, `src/mobile_tiles.rs`, `src/shell/launcher.rs`, `src/desktop.rs`, `config/apps.json`, `config/apps.makepad.json`, `Cargo.toml`.

**Rules for every task:**
- Work on `feat/octosmap`. Commit once per completed task, in the repo's style (`maps: …`, lower case, what the change does). Push nothing.
- Stage only the task's own files. `.gitignore` and `scripts/` carry the person's uncommitted work: never stage them.
- No author names, signatures or AI references in any file or commit message.
- Every framework dependency pins revision `45d5413…`; CI rejects any other (`tools/setup-native.py --check`). CI builds with `--locked`, so `Cargo.lock` is committed whenever the graph changes.
- If an API name in this plan does not compile, find the right name in the reference files above (they compile at this revision) and use that; do not invent alternatives.
- Logic is written test-first: the failing test, then the code. Tests run without a window and without the network: parsers read `tests/fixtures`, the view's tests inject replies.
- Colours come from `Skin::for_vm(vm)` inside `script_mod!`, never literals for skin roles: the host re-runs the module on a light/dark change.
- The first `cargo test -p octosense-maps` compiles Makepad with `maps`; allow 10–20 minutes.

### Accepted changes after Tasks 2–7

These supersede the task text where they differ:

- **`geo.rs` re-exports the navigation library's geometry** (`LonLat`, `haversine_m`, `bearing_deg`, `cumulative_distances`, the Mercator pair) rather than writing its own; it adds the polyline decoder (the widget's is `pub(crate)`), `Bounds`, `fit_camera` and the text.
- **`MapViewAction::PinTapped` is an overlay layer's pin** (the EV-charger layer), not a point of interest of the base map, which has no tap target of its own at this revision. `places::from_pin_info` keeps whatever attributes such a pin carries; on the base map a long press and the reverse lookup are how a spot is picked. Tapping a shop's label is a `BACKLOG.md` entry.
- **`Place` has a `kind`** (`PlaceKind`: place, food, shop, transit, lodging, street) for its row's icon, beside the `category` text.
- **A step has an `Arrow`, not a `ManeuverKind`:** the list shows lines the session does not announce (going straight on, a road changing its name), so `Arrow` adds `Straight`. `Directions::maneuver_steps` maps each announced maneuver to its line, and the banner reads that line's text, which knows a fork from a ramp. Lane hints, notices and roundabout exits are folded into the line before them. The OSRM fixtures keep `bearing_after` for `Head southwest on …`.
- **Guidance takes `dt`, not a clock,** so it tests without a platform; its `NavTick` carries the matched position for the puck, the step's arrow and the distances as numbers (the view formats them in the person's units). A preview lasts between 20 and 90 seconds whatever the route. A reroute is asked for once per episode off the route and again after 15 seconds if it lasts.
- **Both ends of a route are an `End`** (`MyLocation` or a place), so swap works when the origin is the device's location. `MapsModel::begin_search` takes the point to bias to. `retry_route`, `begin_reroute`, `take_reroute`, `needs_fix` and `cancel_all` joined the model; ending a drive that was rerouted forgets the routes, which no longer start at the origin.
- **No `Hosting`:** News needs it to pick how a link opens; v1 of OctosMap opens none. `set_hosting` is dropped from Tasks 12 and 13.
- **`Settings`** (units, dark map, 3D buildings, labels, the last camera) is what `saved_state` keeps, every field optional on disk; a camera off the map is not restored.
