# 后端 WebView 验收

[English](backend-webview.md) | 简体中文

`backend_webview.py` 通过真实 macOS 宿主和 WKWebView 运行已签名的测试应用。临时 HTTP 服务器不预置账户、授权码或令牌。驱动把虚构凭据输入原生引擎的表单；宿主接收被拦截的重定向、交换 PKCE 授权码，并把所得会话保存在正常的平台凭据库中。

这是虚构后端验收，不是 Google/GitHub 登录测试。Google 继续使用外部浏览器。此前的[浏览器验收](backend-login/README.zh-CN.md)保留为独立测试。

## 运行

提供已构建的 `connected-app-host`、`connected-install` 示例和 App Hub CLI。宿主必须启用非默认的 `mobile-apps,acceptance-fixtures` 功能。输出目录必须是新建的私有目录，不得使用已有用户配置。

```sh
python3 tools/connected-e2e/backend_webview.py \
  --binary "$HOST_BINARY" \
  --installer "$INSTALLER_BINARY" \
  --hub "$HUB_BINARY" \
  --out "$NEW_PRIVATE_RUN_DIRECTORY"
```

原生流程验证：

1. 取消会销毁登录视图，不交换授权码，也不创建账户连接。
2. 等待登录时正常退出宿主进程，不创建连接、不交换授权码；新进程仍未连接。
3. 宿主 Back 能从真实同源页面返回表单。
4. 真实连接错误显示宿主错误提示；Retry 创建新的隔离视图。
5. 注册、错误密码提示、登录、固定回调拦截、PKCE 交换和受保护身份读取均通过真实原生引擎完成。
6. 第二个应用不会收到第一个应用的 Cookie，在自身登录前后都不能使用第一个应用的连接句柄。
7. 服务器在真实表单提交中收到自己设置的 HttpOnly Cookie。驱动不读取或注入 Cookie 值。
8. 新宿主进程恢复连接并读取受保护数据；退出登录撤销本地句柄，后续读取被拒绝。

仅供测试的原生命令文件只有在显式同时提供 `--backend-fixture` 和 `--webview-control` 时才允许 DOM 表单输入和检查。生产登录视图禁止检查。测试控制不提供回调、授权码、Cookie、令牌或账户。命令仅返回执行是否成功，不导出任意 JavaScript 返回值。

## 证据和清理

驱动记录二进制/源码哈希、服务器事件名和状态码、输入确认以及状态断言。WK 原生快照和 Makepad 宿主框架截图是分开的原始图像：Makepad 渲染目标截图不包含操作系统的 WK 子视图。必须分别检查，不能拼合后冒充截图。

功能 PASS 不等于视觉验收通过。发布脱敏记录前应检查原始截图。不要发布整个输出目录：其中含有私有测试控制文件、临时连接元数据和原生日志。虽然账户和端点都是虚构的，授权材料仍必须留在私有运行目录中。

无论成功还是失败，驱动都会尝试通过宿主断开剩余测试账户，并停止自己启动的原生进程和服务器。记录区分已确认的本地句柄撤销与已请求的平台凭据删除，不声称独立读取凭据库验证删除。失败尝试及其准确源码/二进制关联必须保留。

最终 macOS 运行八项检查全部通过；同一二进制的外部浏览器后端回归七项检查全部通过。参见[已检查的记录和原始截图](evidence/backend-webview-20261007/README.zh-CN.md)。另行保留三次历史原生运行：两次初步运行，以及最终 Glance 生命周期修正前的验收运行。

每个应用使用独立的原生宿主进程，访问同一个隔离配置目录。Retry 还验证同一进程内的新 Cookie 存储；没有覆盖同时打开多个应用窗口。等待授权时退出进程的测试发生在提交表单之前。同一进程内替换弹层由独立宿主生命周期测试覆盖。Android 使用自己的原生 Activity 和设备驱动，本 macOS 测试不声称覆盖 Android。
